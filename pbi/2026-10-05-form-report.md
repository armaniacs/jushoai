# PBI: フォーム不具合・改善要望ページの報告（GitHub issue 起票）

状態: 実装済み（as-built を記録して閉じる）

## 背景

特定 URL のフォームのパース失敗、またはユーザーが改善してほしいページを、開発者・運営チームへ直接フィードバックする専用機能。yasumaro（やすまろ）の「不具合を報告」機能に相当する。

## 確定済み要求（2026-10-05 ヒアリング）

- 報告内容は **URL および利用中の LLM モデル情報のみ**
- 起票方式は**実装小**（GitHub の issue 作成ページをプリフィル付きで開く方式を想定。拡張機能からの API 直接起票は行わない）
- 追加1＋追加2（カナ欄対応後の生年月日・学校・複数プロファイル）とは独立したサブシステムのため別サイクルで設計する

## 確定事項（実装による確定）

- 宛先リポジトリ: `https://github.com/armaniacs/jushoai`（`src/feedback/issue-url.ts` の `FEEDBACK_REPO`。origin remote と一致）
- 報告 UI の入口: プレビューの「開発にFBする」チェックボックス（LLM 再分析の成功後に表示）
- プリフィル本文の形式: 件名 `分類FB: 初回NG→LLM再分析OK (host)`、本文に初回/再分析の分類対照と欄メタデータ JSON、ラベル `feedback`。文字数上限は設けず URL 長の制約のみ
- プライバシー注意文: チェックボックスの title に「公開 issue が開きます。プロファイルの値は送りません」を表示（`tests/ui/preview-feedback.test.ts` で検証）
- 要求からの差分: デバッグのため欄メタデータ（label 等）と前後分類も送る。プロファイル値は送らない（`tests/feedback/issue-url.test.ts` で検証）。URL は origin+path のみに正規化する

- [x] プロファイル値を含めないことが自動テストで検証される
