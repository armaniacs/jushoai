# PBI: 非表示・クイック登録ダイアログの a11y（フォーカス・告知・Esc・復帰）

## ユーザーストーリー
スクリーンリーダー・キーボードの利用者として、バナーの X から開くダイアログにフォーカスが移り、出現が告知され、Esc で閉じられてほしい、なぜなら 現状は開いてもフォーカスされず aria-live もなく、X 押下でバナーごと破棄されてフォーカスが body に落ち、15 秒の自動クローズと重なると undo も「起動しないURL」登録も非視覚ユーザーだけが到達できないから

## 実装記録

### 何を・どこに

- `src/ui/dismiss-dialog.ts`
  - ダイアログ分割はせず同一ダイアログ内で整備（System Architect 調整判断どおり）。
  - **フォーカス移動**: 挿入後に有効な最初のボタン（「今回だけ閉じる」）へ `focus()`。`mountPanel` の「first enabled button」の作法と同じ。
  - **出現告知**: `role="status"`（aria-live="polite" 内包）の兄弟領域を Shadow DOM 内の box の外に追加（`preview.ts` の status 行と同じ視覚非表示パターン）。文書に挿入した後に `textContent` を設定（挿入前に満たした live region は読み飛ばす読み上げ器があるため）。告知文: 「JushoAI の非表示ダイアログを開きました。15秒後に自動で閉じます」。
  - **Esc**: `attachEscapeClose` と同種の document keydown（capture）。Esc は「今回だけ閉じる」と同一経路（teardown + onClose、登録は起こらない）。本ダイアログは非モーダルのため、フォーカスがダイアログ内にあるときだけ効く（上に開いた preview / AI guide のモーダルパネルから Esc を奪わない絞り込み）。
  - **フォーカス復帰**: `mountPanel` と同じ方針。開いた時点の位置（opener）が body 以外で接続されていればそこへ戻し、そうでなければ `actions.restoreFocus` が返す page 側の合意位置へ。全クローズ経路（X・Esc・自動クローズ・元に戻す・登録成功の close）が teardown を通るため復帰する。復帰の発火は「クローズの結果フォーカスが body に落ちた場合」（クローズ時点でダイアログ内にフォーカスがあったか、すでに body の場合）に絞った。自動クローズの時点で利用者がすでにページ側の別欄に入力中なら奪い返さない（body 落ちの解消が目的で、入力中のフォーカスを奪うことは意図しない）。`isConnected` を見るため、閉じる時点でフォームが無ければ body に退避（それ以上の合意先がない場合の最後の手段）。
  - **自動クローズの明示**: 本文に「15秒後に自動で閉じます」を追加（`AUTO_CLOSE_NOTICE` const）。本文は可視テキストなのでスクリーンリーダーにも読まれ、告知文にも同じ文言を含めた。
  - **PBI-234 残務**: `setRegisterBusy(false)` が `aria-disabled="false"` を残すのを属性 remove に変更。
- `src/entrypoints/content.ts`
  - X 押下の wiring に `restoreFocus: () => form.anchor.el` を追加。バナーはダイアログが開く前に破棄済みで opener が body に落ちるため、復帰先はフォームの先頭欄（アンカー欄）に合意した。
