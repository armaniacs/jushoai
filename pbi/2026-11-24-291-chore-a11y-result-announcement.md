# PBI: 結果画面の件数を読み上げに伝える

## ユーザーストーリー
スクリーンリーダーを使う利用者として、入力の結果（適用済みの件数と見送りの内訳）を自動で読み上げてほしい、なぜなら結果画面は見出しと件数が差し替えられるだけで発話が起きず、件数に気づけないまま閉じてしまうから

## 区分
改善 / 1.0 後でも可

## 優先度
- 順位: 未採点
- RICEスコア: 未採点
- 根拠: PBI-285 の通し監査で検出（2026-11-24）。`showPreview` の結果表示は `panel.replaceChildren` で内容を差し替えるが、その時点で生きている live region が無い（`role="status"` の `status` は差し替えで DOM から外れる）。キーボード操作は PBI-285 で直した `report.focus()` と `showUndoResult` のフォーカス移動で足りるが、発話は別問題。挿入直後の live region が発話されるかは読み上げ実装に依存するため、実機確認つきで設計する必要がある

## BDD受け入れシナリオ

```gherkin
Scenario: 結果の件数が読み上げられる
  Given スクリーンリーダー (VoiceOver / NVDA) を使っている
  When  プレビューで「入力する」を押し、結果画面に切り替わる
  Then  「適用済み X / Y件」と見送りの内訳が読み上げられる

Scenario: 元に戻した結果が読み上げられる
  Given スクリーンリーダー (VoiceOver / NVDA) を使っている
  When  結果画面で「元に戻す」を押す
  Then  「元に戻しました（X件）」が読み上げられる
```

## 受け入れ基準
- [ ] 結果表示と元に戻し表示のどちらでも、件数の要旨が `role="status"` 等で発話される（実機確認つき）
- [ ] VoiceOver / NVDA のどちらかで記録付きの手動確認を行い、結果を PBI に残す
- [ ] キーボードのフォーカス移動（PBI-285 の `report.focus()` と閉じるボタンへの移動）を崩さない
