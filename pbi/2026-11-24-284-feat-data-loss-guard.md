# PBI: 登録データの消失に備えるバックアップの導線を足す

## ユーザーストーリー
複数のプロファイルを登録した利用者として、拡張の削除やブラウザの再インストールで登録が消える前にバックアップを取れることを知りたい、なぜなら JSON エクスポートはあるが、使う機会を知らせる導線が無く、消えてから気付くから

## 区分
改善 / 1.0 推奨

## 優先度
- 順位: 9 / 17
- RICEスコア: 100 (Reach=50 / Impact=1 / Confidence=80% / Effort=0.4人週)
- 根拠: データは `chrome.storage.local` のみで、同期もクラウド保存もしない設計（意図的）。だからこそ利用者自身のバックアップが唯一の復旧手段になる。機能はあるので導線だけの小さな変更

## BDD受け入れシナリオ

```gherkin
Scenario: 一度もエクスポートしていない利用者に知らせる
  Given プロファイルが 2 件以上あり、エクスポートの記録が無い
  When  設定ページを開く
  Then  バックアップを勧める控えめな通知と「エクスポートする」ボタンが出る
  And   閉じると 30 日は再表示しない

Scenario: 最後のエクスポートからの経過が分かる
  Given 以前にエクスポートしている
  When  設定ページのエクスポート欄を見る
  Then  最後にエクスポートした日付が表示される
```

## 実装記録（2026-11-24、work/ga-readiness）

- 日時の保存場所: 新規キー `jushoai:backup`（`src/storage.ts` の `BackupMeta`。`lastExportAt` と `dismissedAt` のみで、値は保存しない）。`LAST_KEY` の流儀に従い、parse と load と save を用意した。不正な値は parse で落とす。
- 通知の置き場所と根拠: エクスポート節の中に置いた（`transfer-section.ts` の `.backup-nudge` と `.backup-last-export`）。BDD が通知とエクスポートボタンを対にしているため、ボタンがすでにある節が最も控えめで、既存の導線（notice-center のトーストやガイド）を壊さない。バナーやバッジの新設はしていない。
- 条件と再表示間隔: 純粋関数 `src/core/backup-nudge.ts` に切り出した（2 件以上かつ未エクスポートで表示、閉じたら 30 日は再表示しない、境界は単体テストで固定）。節の表示判定は統合テスト、E2E は 1 シナリオ追加。
- 平文注意の確認結果: 既存の注意（節の 1 行とエクスポート前の confirm）に不足はなく、重ねて足さない。受け入れ基準 3 件目は確認済みとして扱う。
- ガイド一致の結果: 節とガイド（日英）の両方に「アンインストールすると登録は消える、消える前に JSON で書き出す」旨の 1 行を足し、文言を一致させた。サイトは節の追加なし（H2 数は不変）で、日英ともに同じ位置の箇条書きに足した。
- E2E の扱い: `tests/e2e/scenarios.ts` に `runBackupNudge` を足し、両ブラウザのスイートに組み込んだ。Chrome 実機（HEADLESS=1）で対象シナリオのみ実行して通過を確認した。全体の e2e-chrome は 26/27 で、残り 1 件（translucent banner の色トークン）は本変更と無関係の箇所の失敗。Firefox 実機が無いため e2e-firefox は未実施。
