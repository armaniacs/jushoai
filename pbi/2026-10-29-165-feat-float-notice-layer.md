# PBI: 設定画面にフローティング通知層を作る

## ユーザーストーリー
利用者として、保存結果を画面のどこにいても見逃したくない、なぜならページ末尾の表示はスクロール位置次第で気づけないから

## ビジネス価値
- 成功・失敗の認知率向上と、エラー放置による後続トラブルの削減
- 測定: 保存結果の見逃し報告の解消

## BDD受け入れシナリオ

```gherkin
Scenario: 成功は数秒で消える
  Given プロファイル画面で保存を押す
  When 保存が成功する
  Then 画面上部にトーストが出て約4秒で消える

Scenario: エラーは閉じるまで残る
  Given 住所が空の状態
  When 住所画面で保存を押す
  Then 画面上部に固定バナーが出て×を押すまで残る

Scenario: 新しい通知は置き換わる
  Given 通知が表示されている
  When 次の保存結果が出る
  Then 同枠の内容が置き換わる（成功タイマー再始動）
```

## 受け入れ基準
- [ ] `#float-root`（上部固定・前面）にガイド枠＋通知枠がある
- [ ] 成功トーストは約4秒で自動消去される
- [ ] エラーは×か次の通知まで残留し、切り詰めは5件＋他N件のまま
- [ ] 保存後のタブ誘導ボタンは通知枠内のアクションとして出る
- [ ] プロファイル／住所ページの通知が浮動に移行し、他セクションは inline のまま
- [ ] `make check` が緑

## 技術的考慮事項
- 依存関係: なし。`notice()` は他セクション用に残す
- 非機能要件: エラーは role=alert、成功は aria-live polite

### 実装手順

4. `make check` で緑を確認する
