# PBI: フローティング入力ボタンを半透明にして下の入力が見えるようにする

## 背景

「JushoAI で入力」ボタン（`src/ui/button.ts` の `.wrap` スタイル）が不透明な青ベタのため、入力欄に重なったときに下の文字が一切見えなくなる。161（重ねない配置）が根本対策だが、配置だけでは覆い尽くせない画面（狭い・密なフォーム）が残るため、重なっても下が見える緩和策として半透明化する。

なぜなぜ分析の要点: 半透明は「見える」を回復するが「押せる・選べる」は回復しない（ボタンの矩形はポインタを奪い続ける）。単独では不便は解消しないため、161の後に重ねる緩和策と位置づける。

## ユーザーストーリー

フォーム入力者として、ボタンが入力欄に重なっても下の文字が透けて見えてほしい、なぜなら値を確認しながら入力を続けたいから。

## 技術的考慮事項

- 依存関係: 161の後（配置が変わると重なり前提が変わるため）。163と同ファイルのため直列161→162→163
- 対象: `src/ui/button.ts`（CSS のみ。`button.ts` の配置ロジック・`host.ts` には触らない）
- 非機能要件: ホバー・フォーカス時は必ず不透明に戻す（可読性と操作性）。`prefers-reduced-transparency` 相当の配慮があれば尚可

## 深掘りで確定した設計判断（2026-10-27）

- 手法: 要素全体の `opacity` は使わない。`.wrap` の背景色（#2457d6）を alpha 付きにして背景だけ透けさせ、文字・バッジは不透明のまま（ユーザー確定）
- 適用: 常時（161の重なり検出と連動しない）。161が解なし（全候補が重なる）場合の緩和も兼ねる
- 濃度: 下の入力とボタン文言の双方が判読できる値を具体定数として残し、コントラストを確認する

## 実装者向け注記

### 現状コードの確認（着手前に必ず実行すること）

```bash
grep -rn "mountButton\|\.wrap" src/ui/button.ts tests/ui/button.test.ts
```

CSS のみの緩和策であり、クリックの塞がり自体は解消しないことを理解して着手すること。

### 実装手順

1. 重なり時の判読（背景 alpha<1）の検証を赤で書く
2. `.wrap` の背景色を alpha 付きにして背景だけ透けさせ（文字・バッジは不透明のまま）、`:hover`/`:focus-within`/`:active` で不透明に戻す
3. バッジの状態色（error/not-configured 等）が判別できることを目視＋テストで確認

### 落とし穴

- 半透明にしてもポインタは奪われる（入力欄のクリック・選択は塞がれたまま）。「見える＝直った」と誤認しない
- 透明度を上げすぎるとボタン文言が読めなくなる。下の入力とボタンの双方が読める濃度に留める
- `all: initial` のリセット下にあるため、必要なプロパティは Shadow 内スタイルで明示する
