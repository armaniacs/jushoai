# PBI: ツールバークリックで入力内容の確認ポップアップを開く

状態: 実装済み（`make check` green、コードレビューと実機操作はユーザー作業として残す）

## ユーザーストーリー
注入前に内容を確かめたい利用者として、ツールバーのロゴを押して入力内容の確認がほしい、なぜなら何が入るか分からないままフォームに向かうのが不安だから

## 優先度
- 順位: 2 / 3
- RICEスコア: 8.5（Reach=8 / Impact=2 / Confidence=0.8 / Effort=1.5）
- 根拠: ギア（順位3）がこのポップアップに依存するため先行する

## 背景
- 現状はポップアップが存在しない（`src/entrypoints/` に popup 系がなく、`wxt.config.ts` の manifest に action 設定もない）。ツールバーのロゴを押しても何も起きない
- `storage` 権限は取得済み（`wxt.config.ts`）のため追加の権限は要らない
- 選択状態（どのプロファイル・住所を使うか）はプレビュー実行時のメモリ上にしかなく、永続化されていない。ポップアップ側からは直前の選択が分からないため、一覧の確認画面にする（先頭を既定表示）
- 実装時の確定: content が `jushoai:last` に保存していることが分かったため、前回使用に使用中表示を付け、無い場合は先頭を既定表示にする

## BDD受け入れシナリオ
Scenario: 保存内容を確認する
  Given プロファイルと住所を保存済みである
  When ツールバーのロゴを押す
  Then プロファイルの一覧（名前と氏名）と住所の一覧（名前と概要）が表示される

Scenario: 未保存の状態で開く
  Given プロファイルも住所も未保存である
  When ツールバーのロゴを押す
  Then 未登録の旨と設定画面への案内が表示される

## 受け入れ基準
- [x] ツールバーのロゴ押しでポップアップが開く（WXT の popup として登録される）
- [x] 保存済みのプロファイルと住所の一覧が表示される
- [x] 表示する値はローカルストレージから読むだけで、外部に送信しない
- [x] 未保存時はその旨と設定への案内が出る

## テスト戦略
- E2E: ツールバーからポップアップを開く（手動）
- 統合: 保存データの有無で表示が切り替わる
- 単体: fixture の `StoredData` から一覧表示モデルを作る関数のテスト
