# PBI: 適用直前の検証点を host 中央から承認ボタンの矩形に厳密化する

状態: 未着手（コードレビュー 2026-10-11 の Suggestions #1 から起票）
起票日: 2026-10-11

## ユーザーストーリー

プロファイルで入力する利用者として、承認ボタンを覆い隠された状態では注入が中止されてほしい。なぜなら、現行の検証点は host 中央であり、ボタン上だけを覆う要素は検証をすり抜けるから。

## 優先度

- 順位: 3 / 全候補 8 件
- RICEスコア: 35（Reach=100 / Impact=1 / Confidence=70% / Effort=2）
- 根拠: 注入の全フローが対象だが、悪用には覆いと実クリックの誘導が要る。PreviewHandle への検証窓の追加で Effort=2。#2・#3 と同一ファイルのため直列に実施し、本 PBI を先にする（形状を決めるため）

## BDD受け入れシナリオ

```gherkin
Scenario: 承認ボタンが覆われているときは適用が中止される
  Given 承認ボタンの矩形を覆う要素がある
  When  利用者が適用を試みる
  Then  注入は中止され、理由が表示される

Scenario: ボタンが可視で最前面のときは従来どおり適用できる
  Given 承認ボタンが可視で最前面にある
  When  利用者が承認を押す
  Then  承認どおりに値が注入される
```
