# PBI: オプション画面の保存をプロファイル／住所で分離する

## ユーザーストーリー
初回利用者として、プロファイルだけ入力した状態で保存したい、なぜなら住所未入力のエラーで「この画面の何が足りないのか」と迷いたくないから

## ビジネス価値
- プロファイル入力→保存→住所入力→保存の順に進めるようになり、初回離脱を減らせる
- エラーは今見ている画面の項目だけになるため、問い合わせ・誤解を減らせる
- 測定: 初回でプロファイル保存成功に至る割合、住所エラー混入の保存失敗件数の減少

## BDD受け入れシナリオ

```gherkin
Scenario: プロファイルだけ先に保存できる
  Given 有効なプロファイル1件を入力し住所は空のまま
  When プロファイル画面で保存を押す
  Then プロファイルは保存され住所のエラーは表示されない
  And 成功表示に次は住所を入力する誘導が出る

Scenario: 住所画面では住所だけが検証される
  Given プロファイル画面の保存済み状態で住所が空
  When 住所画面で保存を押す
  Then 住所の不足だけが表示されプロファイルのエラーは表示されない

Scenario: 反対側が未完成でも保存を邪魔しない
  Given プロファイルは有効で住所が未入力
  When プロファイル画面で保存を押す
  Then 保存は成功し住所エラーでブロックされない
```

## 受け入れ基準
- [x] プロファイル保存はプロファイルの検証だけ行い、住所の状態を見ない
- [x] 住所保存は住所の検証だけ行い、プロファイルの状態を見ない
- [x] 各画面に保存ボタンがあり、共有フッターの一括保存になっていない
- [x] 保存成功時、反対側が未完成なら誘導（住所タブへの移動手段付き）を表示する
- [x] フォームからの取り込みは両画面から実行でき、保存は各画面で確定する
- [x] `make check` が緑

## テスト戦略（t_wadaスタイル）

### E2Eテスト
- プロファイル入力→保存成功→誘導から住所画面へ移動→住所入力→保存成功の通し確認（手動または既存E2E流用）

### 統合テスト
- options レンダリング: プロファイル画面に保存ボタンがあり、住所未入力でも住所エラーを出さないこと
- 住所画面の保存がプロファイルエラーを出さないこと
- 誘導ボタンが住所タブへ遷移すること

### 単体テスト
- プロファイル側の検証入力→ `validateProfile` のみで判定されること
- 住所側の検証入力→ `validateAddress` のみで判定されること
- 空リスト時の件数チェックが各側で独立に働くこと

## 実装アプローチ
- **Outside-In**: 画面シナリオ（保存分離のE2E相当の確認）から開始し、失敗を確認してから実装
- **Red-Green-Refactor**: TDDサイクルを各レイヤーで適用
- **リファクタリング**: グリーンになるたびに品質改善

## 技術的考慮事項
- 依存関係: なし（`saveData` のID単位マージで反対側を消さないことを利用）
- テスタビリティ: 検証スコープを関数分離し、画面テストは既存方針（typecheck＋手動）に従う
- 非機能要件: 既存の正規化・検証ロジックは変えない。`isReady`・注入・分類は対象外

## 実装者向け注記

### 現状コードの確認
（着手前に必ず実行すること）
```bash
grep -rn "onSave\|validateProfile\|validateAddress" src/entrypoints/options/
grep -rn "saveData\|mergeStoredData" src/storage.ts
```

確認済み（2026-10-28）: 共有 `onSave` が両方を一括検証するのみで、ページ別保存は未実装。`saveData` はID単位マージのため片側保存でも反対側を消さない。

### 実装手順
1. E2E相当の確認を先に書く（プロファイルのみ保存成功→住所エラーなし）
2. options の保存処理を分離する（プロファイル保存／住所保存、各画面にボタン配置、共有フッター廃止）
3. 成功時メッセージに反対側未完成の誘導（タブ移動）を追加する
4. 取り込みボタンの配置を両画面で使える形に整える
5. `make check` で緑を確認し、手動で初回フローを通す

### 落とし穴
- フッターは両セクションで共有されているため、切り離し時に取り込み・転記セクションの再表示（`transferHolder` の付け替え）を壊さないこと
- 片側保存時に空配列を渡すとマージで反対側が残る振る舞いを tests で確認すること（削除の復活仕様と混同しない）
- 不可視セクションのエラーを出さないこと（今見ている画面の項目だけ表示）
