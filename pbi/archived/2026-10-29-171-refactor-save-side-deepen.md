# PBI: 片面保存のsaveSide集約

## ユーザーストーリー
開発者として、プロファイル・住所の片面保存フローを単一モジュールにまとめたい、なぜなら同形の複製2経路に副作用順序の差異が埋もれており、保存失敗時の状態不整合が起きるため

## 優先度
- 順位: 3 / 12
- RICEスコア: 128（Reach=20 / Impact=2 / Confidence=80% / Effort=0.25人月）
- 根拠: ホットスポット直撃で実バグ類型を含む。OPT-2とは配置分離で並列可（本PBIはsave-side.tsを新設）

## BDD受け入れシナリオ
Scenario: 保存失敗時にメモリ状態が汚れない
  Given 保存が失敗する条件がある
  When 片面保存を実行する
  Then エラー表示が出て、メモリ上の状態は保存前のままである

Scenario: 両面で同じ規律が守られる
  Given プロファイル面と住所面がある
  When それぞれ保存・失敗させる
  Then 検証→再読込→保存→確定の順序が両面で一致する

## 受け入れ基準
- [x] kind別の差分が単一テーブル・単一関数で表現されている
- [x] 失敗時のstate不変が固定されている
- [x] 両面×空・不正の分岐テストがある

## テスト戦略
- E2E: 保存・失敗時の表示と状態
- 統合: 設定ページの保存フロー
- 単体: 分岐表テスト（storageなし）
