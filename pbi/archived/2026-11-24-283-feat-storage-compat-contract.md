# PBI: 保存データの互換性を 1.0 の約束として固定する

## ユーザーストーリー
長く使う利用者として、拡張の更新でプロファイルや住所が消えたり壊れたりしないことを望む、なぜなら登録し直しは手間で、正式版ではデータを預け続ける前提になるから

## 区分
改善 / 1.0 必須

## 優先度
- 順位: 7 / 17
- RICEスコア: 320 (Reach=100 / Impact=2 / Confidence=80% / Effort=0.5人週)
- 根拠: `storage.ts` の `migrateData` は旧形式の読み込みと破損耐性を持つが、保存形式に明示的な版番号が無く、「将来の版が書いたデータを古い版が読んだとき」の振る舞い（ストアのロールバック時に起きる）が約束されていない。役割別プロファイルや学年・塾名など 0.1.3x 後半で項目が増えており、1.0 で区切るのに適した時期

## BDD受け入れシナリオ

```gherkin
Scenario: 過去の各版の保存データを 1.0 が読める
  Given 0.1.20 / 0.1.30 / 0.1.39 の各版で保存したデータの fixture がある
  When  1.0 が読み込む
  Then  全項目が失われずに読め、保存し直しても値が変わらない

Scenario: 未来の版が書いたデータを壊さない
  Given 1.0 より新しい版番号と未知の項目を含む保存データがある
  When  1.0 が読み込み、利用者が別の項目を編集して保存する
  Then  未知の項目と版番号は保持され、利用者には更新を促す表示が出る
```

## 実装記録（2026-11-24、Task 6）

- 版番号の置き場所と初期値: `src/storage.ts` の `FORMAT_VERSION = 1` が唯一の置き場所。保存形は `{ version, profiles, addresses }` で、版番号の無い既存データは読み込み境界で版 0 として受け入れる（`storedFormatVersion` が版の無い・壊れた値を 0 に丸める）。保存時（`saveData`・`saveImported` の両経路）は版 0 または現行版を 1 に上げて書き、新しい版は下げずに保持する。将来版を出す手順: 新しい項目を `Profile`・`Address`・空テンプレートに追加し、読み込み側の既定値補完を確認してから `FORMAT_VERSION` を上げる。上げる前に新旧両方向の往復テストを `tests/storage-compat.test.ts` に足す。
- 未知項目保持の直し方: 落とし穴どおり `toTransferJson` の `pickKnown` だけが問題ではなかった。`normalizeProfile`・`normalizeAddress` が既知キーのみ再構築していたため、設定ページの編集・保存とファイル取り込みの両経路で未知キーが落ちていた。`unknownEntries`（`src/core/profile.ts`）を足し、正規化とエクスポートで既知キーの整形後に未知キーを継ぎ足す形に変えた。読み込み境界（`coerceStrings` の spread）は元から未知キーを保持していた。エクスポートは版番号だけ `FORMAT_VERSION` を刻み、未知の項目キーは保持する（版だけ新しいファイルはこの版が再取り込みできる必要があるため）。
- 表示の出し方と根拠: 版ずれ（`version > FORMAT_VERSION`）は読み込めて既知項目は通常動作し、設定ページの転送の節に1行の段落で更新促進の表示を出す（`保存データの形式が新しい版（N）で保存されています。拡張を更新してください。`）。新規のバナーやバッジは足さない。根拠: 版ずれは利用者の操作では直せない（拡張の更新が必要な）状態であり、データを管理する転送の節で気づければ足りる。読み取り失敗時は表示を出さない（既存の読み込み失敗通知に任せる）。
- fixture の出どころ: `tests/fixtures/storage-compat.ts`。0.1.20 はローカルタグが無い（`v0.1.20` が存在せず `git describe` では `v0.1.19-3-g40b643a`）ため、版上げコミット `40b643a` の `src/core/types.ts` で型を確認した。0.1.30 はタグ `v0.1.30`、0.1.39 はタグ `v0.1.39` の同ファイルで確認した。住所のキー集合は3版とも同一、プロファイルは 0.1.20 基本形、0.1.30 会社3項目追加、0.1.39 役職追加の順に増えている。値はいずれも架空の値。
- テスト: `tests/storage-compat.test.ts`（版の解釈、3版の黄金往復、新版データの編集・保存の保持、正規化の継承、エクスポートの版と保持、新版ファイルの拒否）と `tests/options/transfer-section.test.ts` の版ずれ表示2件。`storage.test.ts` の3件は意図した振る舞い変更に合わせて期待値を更新した（エクスポートの envelope 化、未知キーの保持、再読み込み失敗時の版刻印）。
