# PBI: AI設定の認証エラー文をAPIキー確認とOLLAMA_ORIGINS確認に割る

## ユーザーストーリー
接続に失敗した利用者として、読んだ順に手を打てるエラー文がほしい、なぜなら1文に条件が二重だと何を先に確認すべきか分からないから

## 優先度
- 順位: 3 / 7
- RICEスコア: 40.0（Reach=8 / Impact=0.5 / Confidence=1.0 / Effort=0.1）
- 根拠: クラウド・ローカル利用で認証に失敗した人に届く。工数は1文修正

## 背景
- `src/entrypoints/options/ai-section.ts:25` が「API キーを確認してください。Ollama など〜場合は、API キーではなく〜を確認してください」と1文に二条件を詰めている
- 置き換え案: `認証に失敗しました。まず API キーを確認してください。Ollama などローカルのサーバーの場合は、OLLAMA_ORIGINS の設定（拡張機能のオリジンの許可）を確認してください。`

## BDD受け入れシナリオ
Scenario: 認証エラーを読む
  Given 認証に失敗した状態である
  When エラー文を読む
  Then 確認手順が順に書かれている

Scenario: 意味が変わらない
  Given 修正後のエラー文である
  When 条件を比べる
  Then API キー確認と OLLAMA_ORIGINS 確認の両方が残っている
