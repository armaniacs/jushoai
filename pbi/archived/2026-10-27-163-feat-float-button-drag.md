# PBI: フローティング入力ボタンをマウス等で移動できるようにする

## 背景

「JushoAI で入力」ボタン（`src/ui/button.ts` の `mountButton`、固定ホスト `src/ui/host.ts`）は表示位置が自動計算のみで、ユーザーがどかす手段がない。重なったときに自力で回避できないのが不便の核心。161（重ねない配置）が根本対策、162（半透明）が緩和策で、本件は最終手段の手動回避としてドラッグ移動を付ける。

なぜなぜ分析の要点: ドラッグは発見しにくい・手間が残る（Reach狭・Impact中）。実装もポインタ捕捉・クリックとの区別・キーボード操作・自動追従との競合があり、3件中で最も重い。よって順位は3番目。

## ユーザーストーリー

フォーム入力者として、邪魔な位置に出た「JushoAI で入力」ボタンを自分でどかしたい、なぜなら自動配置だけでは塞がりが残る画面があり、その場でしのげないと入力が止まるから。

## 技術的考慮事項

- 依存関係: 161の後。162と同ファイル（`button.ts` CSS/DOM）のため直列161→162→163
- 対象: `src/ui/button.ts`（ドラッグ配線・ユーザーオフセット保持）、必要なら `src/ui/position.ts`（自動位置＋手動オフセットの合成）、`tests/ui/button.test.ts`
- 非機能要件: Shadow DOM（closed）内でポインタイベントを扱う。ページの文字列は `textContent` のみ。位置の保持はタブ内メモリに留め、永続化しない（設定・プロファイル値と混ぜない）

## 深掘りで確定した設計判断（2026-10-27）

- 所有権: 手動移動したらそのタブでは自動追従（anchor 基準の再計算）を止める（ユーザー確定）。content.ts がスクロール毎フレームで全 mounted ボタンに `reposition()` を呼ぶ（`src/ui/panel.ts:159-185`）ため、button.ts 内の manual フラグで上書きを防ぐ。復帰は破棄・再表示のみ
- アンカー相対オフセットの保持はしない（次の欄の隣接欄に再び重なり、161の成果を無効化し得るため）
- 発見性: ドラッグ可能を示す手がかり（grip 表示・grab カーソル・title 属性）を付ける
- タッチ: `touch-action: none` と `pointercancel` を処理し、ページスクロールと競合させない

## 実装者向け注記

### 現状コードの確認（着手前に必ず実行すること）

```bash
grep -rn "mountButton\|reposition\|isTrusted" src/ui/button.ts src/entrypoints/content.ts tests/ui/button.test.ts
```

ドラッグは新規挙動であり、既存の自動追従（scroll/resize/geometry での `reposition`）との競合点であることを確認して着手すること。

### 実装手順

1. E2E（ドラッグで重なりゼロ）を赤で書く
2. ポインタ操作を付ける（`pointerdown/move/up`＋`setPointerCapture`、移動しきい値でドラッグ/クリックを分岐）
3. 手動移動したらそのタブでは自動追従を止める（manual フラグで `reposition` の上書きを防ぐ。復帰は破棄・再表示のみ）
4. キーボード移動（矢印キー＋修飾子等の線引き）を付け、フォーカス可視性を保つ
5. グリーン後にスクロール・リサイズ・拡大縮小での迷子を潰す

### 落とし穴

- クリックとの区別なしに `click` を殺すと入力開始が壊れる。移動距離しきい値を必ず設ける
- 固定ホストの座標は `setProperty(..., 'important')` で書く（通常代入は `all: initial !important` に負ける）
- 自動追従が毎回手動位置を上書きするとドラッグが無意味になる。所有権（自動/手動）を明確にする
- タッチ・ペン・高DPI・ズームでの座標系（viewport 固定 vs document）を取り違えない（`button.ts` は viewport 固定で計算している）
