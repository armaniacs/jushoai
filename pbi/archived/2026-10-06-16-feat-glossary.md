# PBI: ガイド群の前提語彙を集めた用語集を新設する

## ユーザーストーリー
ガイドを読む利用者として、分からない言葉をその場で確かめたい、なぜならプロファイル・住所・プレビュー・AI判定・監査ログの定義が各所に散り、何が前提か分からないから

## 優先度
- 順位: 7 / 7
- RICEスコア: 4.0（Reach=8 / Impact=1 / Confidence=0.5 / Effort=1.0）
- 根拠: 価値はあるが置き場所（新ガイド・既存末尾）と日英 H2 整合の設計が残る（Confidence 0.5）。スコアより設計の重さを優先し最後に置く

## 背景
- 5語（プロファイル・住所・プレビュー・AI判定・監査ログ）が全ガイドの前提だが、定義の末尾一覧がない
- 候補の置き場所: トラブルシューティング末尾・新規ガイド・how-it-works 末尾。新規ガイドなら日英対・ガイド一覧・i18n の扱いも決める（なぜなぜ分析の解は台帳にある）

## BDD受け入れシナリオ
Scenario: 分からない言葉を引く
  Given ガイドを読んでいて用語に詰まった
  When 用語集を開く
  Then 5語の意味が1箇所で分かる

Scenario: サイトが壊れない
  Given 用語集を追加した
  When `make site` を実行する
  Then 日英のキーと H2 数が一致し検査が通る

## 受け入れ基準
- [x] 5語の定義が1箇所にある
- [x] 各定義が本文の用法と矛盾しない
- [x] `make site` が通る（新規ガイドなら日英対で用意する）

## テスト戦略
- E2E: `make site-serve` で目視する（手動）
- 統合: `make site` の検査（日英キー・H2 数の一致）
- 単体: なし（文書のみ）
