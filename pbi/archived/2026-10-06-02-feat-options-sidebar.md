# PBI: 設定ページに左メニューを導入する

状態: 実装済み（`make check` green、コードレビューはユーザー作業として残す）

## ユーザーストーリー
設定を編集する利用者として、左メニューで目的の節に移動したい、なぜなら設定項目が増えて縦スクロールだけでは目的の節にたどり着きにくいから

## 優先度
- 順位: 1 / 2
- RICEスコア: 8.5（Reach=8 / Impact=2 / Confidence=0.8 / Effort=1.5）
- 根拠: 不具合報告の配置（順位2）がこのメニュー構造に依存するため先行する。スコア自体は順位2より低いが依存を優先した

## 背景
- 現状は `src/entrypoints/options/index.html` が `max-width: 640px` の1列で `#app`（プロファイル・住所）と `#ai-app`（AI判定）を縦に積む
- `src/entrypoints/options/main.ts` と `ai-section.ts` が節を増やすほどページが縦に伸びる
- 参照した Yasumaro の設定画面は左に節の一覧、右に内容という配置である

## BDD受け入れシナリオ
Scenario: 左メニューから目的の節に移動する
  Given 設定ページを開いている
  When 左メニューの「住所」を選ぶ
  Then 住所の節が見える位置に移動する

Scenario: 小さい幅でも設定を編集できる
  Given 幅の狭いウィンドウで設定ページを開いている
  When プロファイルの値を編集して保存する
  Then 従来と同じ validation と保存が動作する

## 受け入れ基準
- [x] 左メニューに `プロファイル` / `住所` / `AI 判定` の3項目がある
- [x] メニュー選択で対応する節へ移動できる（anchor または focus 移動）
- [x] 現在位置に対応するメニュー項目が視覚的に分かる
- [x] 既存の保存・validation・ダークモードの見た目を壊さない
- [x] ページ由来の文字列は `textContent` で入れ `innerHTML` を使わない

## テスト戦略
- E2E: 設定ページを開きメニュー選択で各節へ移動する（手動）
- 統合: `main.ts` の render と `mountAiSection` が同一文書で節 id を共有する
- 単体: 節 id とメニュー項目の対応表のテスト（追加する場合）
