# PBI: 左メニューの最下部に不具合報告を置く

状態: 実装済み（`make check` green、コードレビューはユーザー作業として残す）

## ユーザーストーリー
入力がうまくいかない利用者として、設定画面の左メニュー最下部から不具合を報告したい、なぜならプレビュー経由の報告入口だけでは失敗時に報告手段が見つからないから

## 優先度
- 順位: 2 / 2
- RICEスコア: 20.0（Reach=3 / Impact=2 / Confidence=1.0 / Effort=0.3）
- 根拠: スコアは最上位だが左メニュー（順位1）に依存するため後に配置する。依存はスコアより優先した

## 背景
- 既存の報告入口はプレビューの「開発にFBする」チェックボックスのみで、LLM 再分析の成功後に表示される（`src/ui/preview.ts`）
- 報告先は `src/feedback/issue-url.ts` の `FEEDBACK_REPO`（`https://github.com/armaniacs/jushoai`）で issue 起票ページをプリフィル付きで開く方式である（`pbi/archived/2026-10-05-form-report.md`）
- 設定ページには分類前後の snapshot がないため、同じ本文は作れない
- 参照した Yasumaro の設定画面は左メニューの最下部に報告入口がある

## BDD受け入れシナリオ
Scenario: 設定画面から不具合報告を開く
  Given 設定ページを開いている
  When 左メニュー最下部の「不具合報告」を選ぶ
  Then issue 起票ページが新しいタブで開く

Scenario: 報告に個人情報を含めない
  Given 設定ページを開いている
  When 「不具合報告」のリンク先を確認する
  Then プロファイル値・住所値を含まず、版数と再現手順の雛形だけを含む

## 受け入れ基準
