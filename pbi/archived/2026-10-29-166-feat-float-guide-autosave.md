# PBI: 初回ガイドを浮動化しお試しを即時登録にする

## ユーザーストーリー
初回利用者として、次にやることを迷わず選びたい、なぜなら試す・名前を登録する・住所を登録するの導線がないと手が止まるから

## ビジネス価値
- 初回離脱の削減と試用から定着への転換率向上
- 測定: 初回バナー表示→有効保存に至る割合

## BDD受け入れシナリオ

```gherkin
Scenario: 3ボタンから選べる
  Given 有効プロファイル0件で設定画面を開く
  When ガイドを見る
  Then 「架空の名前と住所を作って試す」「名前を登録する」「住所を登録する」がある

Scenario: 試し一押しで登録される
  Given 初回状態
  When 「架空の名前と住所を作って試す」を押す
  Then 保存ボタンなしで登録され「架空の名前として…さん（…在住）を作りました」と出る

Scenario: 登録系ボタンはタブへ誘導する
  Given 初回状態
  When 「名前を登録する」を押す
  Then プロファイルタブへ移動する（住所版は対称）

Scenario: ガイドは閉じても条件内なら復活する
  Given 初回状態で×を押す
  When ページを再読み込みする
  Then ガイドが再表示される（有効保存後は出ない）
```

## 受け入れ基準
- [x] ガイド枠に見出し＋3ボタンがあり、試しボタン文言は新文言
- [x] 試し一押しで両側が検証・保存され、名前入りトーストが出る
- [x] 既存の無効値がある場合は浮動エラーに項目表示し上書きしない
- [x] ×はセッション内非表示、旧 inline 配置は廃止

- [x] `make check` が緑

## 実装者向け注記

### 現状コードの確認
```bash
grep -n "fillBlanksWithSample\|お試し入力" src/entrypoints/options/main.ts
```

確認済み（2026-10-29）: 試し入力は充填のみで保存は手作業。文言は旧「お試し入力」。

### 実装手順
1. E2Eを即時登録版に更新し失敗を確認する
2. ガイド枠に3ボタンを載せ、試し処理に保存まで持たせる（両側検証→保存、失敗は浮動エラー）
3. `trialToastText` を純粋関数に切り出して単体テストする
4. 旧文言の参照（実装・テスト・E2E）を新文言に更新する
5. `make check` で緑を確認する

### 落とし穴
- 試し保存は両側とも検証を通してから保存すること（未検証混入の再発防止）
- E2Eの保存ボタン xpath は節に絞ること（両ページ同名）
