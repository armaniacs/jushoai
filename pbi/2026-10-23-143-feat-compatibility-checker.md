# PBI: 診断・相性チェッカー（入れられる率の表示と赤裸化報告）

## ユーザーストーリー
入力できなかった利用者として、このフォームは何％入れられるかと理由を知りたい、なぜなら黙って入らないより理由が分かれば諦めがつき、報告すれば直る見込みがあるから

## 優先度
- 順位: 7 / 8
- RICEスコア: 87.5（Reach=250 / Impact=1 / Confidence=70% / Effort=2人週）
- 根拠: 報告→fixture化（`make addurl`）の導線になり、PBI-136（eval）の現場版。直接の入力価値は小さい

## BDD受け入れシナリオ
Scenario: 相性が分かる
  Given 入力できない欄があるフォーム
  When 診断を開く
  Then 欄ごとの分類結果・つまり箇所・理由が見える

Scenario: 報告は個人情報を含まない
  Given 診断結果を報告する
  When Issue報告用の文面を作る
  Then プロファイル値・欄の現在値は含まれず、メタデータのみで`make addurl`の起点になる

## 受け入れ基準
- [ ] 診断は読み取りのみで注入・保存しない
- [ ] 報告文面に個人情報を含めない（Issue注意書きと整合）
- [ ] ページ由来文字列は`textContent`のみで表示し`innerHTML`を使わない

## テスト戦略
- E2E: 実フォームでの診断表示の目視確認
- 統合: 診断→報告文面の生成テスト
- 単体: 相性率・理由判定ロジックの単体テスト
