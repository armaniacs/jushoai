# PBI: 充填結果の可視化（部分適用・不適用に気づけるようにする）

## ユーザーストーリー

- フォーム利用者として、自動入力を実行した後に、一部の欄だけが適用されなかったり、まったく適用されなかったりした場合に、その事実に気づきたい。適用されたつもりで送信してしまう手戻りを防ぎたい。
- 開発者として、適用できなかった発生の内訳（無効な選択肢・外れた入力欄・入力済みによる見送りなど）を数えられるようにしたい。発生率を把握して改善につなげたい。

## 優先度（順位・RICEスコア・根拠）

- 順位: 1位 / 12件
- RICEスコア: 333（Reach=100 / Impact=1 / Confidence=50% / Effort=0.15人月）
- 根拠: ユーザーが目にする充填の完全性に直結し、全候補中で最高スコア。依存する先行案件がなく、単独で着手できる。見た目・文言・操作フローは変えない範囲で行うため、既存利用者への影響がない（従来も適用結果は通知されていなかったため、後方互換の懸念なし）。

## BDD受け入れシナリオ

### シナリオ1（ハッピーパス）: すべての欄が適用できたら完了が分かる

```gherkin
Given プレビューで承認待ちの入力欄が複数ある
When 利用者が適用を承認し、すべての欄に値が入る
Then 適用が完了したことが分かる表示または記録になる
And 適用できなかった欄があるかのような通知は出ない
```

### シナリオ2（エラー・境界）: 無効化された選択肢がある場合は適用せずに分かる

```gherkin
Given 承認から適用までの間に選択肢が無効化されたラジオ欄がある
When 利用者が適用を承認する
Then 無効化された選択肢への値は入力されない
And 適用できなかった欄があることが利用者に分かる（ボタン表示または開発者向けの記録のいずれか）
```

### シナリオ3（エラー・境界）: 入力欄が差し替え・入力済みで適用できない場合も沈黙しない

```gherkin
Given 承認から適用までの間にページ側で差し替えられた入力欄や、既に入力済みの欄がある
When 利用者が適用を承認する
Then 差し替えられた欄への入力は行われない
And 入力済みの欄は上書きされない
And 適用できた件数と適用できなかった件数の内訳が確認できる（ボタン表示または開発者向けの記録のいずれか）
```

## 受け入れ基準（チェックボックス）

- [x] 適用後に、すべて適用できた場合と、一部または全部が適用できなかった場合を区別できる
- [x] 無効化された選択肢への値の入力が発生しない
- [x] ページ側で差し替えられた入力欄への値の入力が発生しない
- [x] 入力済みの欄が上書きされない
- [x] 適用できなかった内訳（無効な選択肢・外れた入力欄・入力済みによる見送りなど）が数えられる形で残る
- [x] ボタンの見た目・文言・基本の操作フローが変わらない

## テスト戦略（E2E/統合/単体）

- E2E: 実ブラウザでサンプルフォームを開き、適用後に完了表示が出ること、および選択肢の無効化・入力欄の差し替えを再現したページで適用できない旨が利用者に伝わることを確認する
- 統合: 承認から適用までの一連の流れで、適用結果の集計がボタン表示または開発者向けの記録に届くことを確認する（無効化・差し替え・入力済みの混在を含む）
- 単体: 適用可否の判定（無効な選択肢は選ばない、外れた入力欄には入れない、入力済みは上書きしない、適用できた件数とできなかった件数を数える）の分岐を網羅する

## 実行記録（2026-10-19・徹底精査）

- E2E（実ブラウザ）: `HEADLESS=1 E2E_NO_SANDBOX=1 npx vitest run -c vitest.e2e.config.ts chrome` → **7/7 green**（fill flow 2件・部分適用2件・settings 1件・excluded 2件）。初回はsandbox起因のセッション断で全skip、E2E_NO_SANDBOX=1で解消。新規fixture `tests/e2e/pages/partial-notice.html`＋`badgeNotice` ヘルパー（harness）を追加
- 統合: `make check` 内 samples 統合 green
- 単体: `make check` 全体 green
- 徹底精査の核心所見: シナリオ2・3の「利用者への通知」は planner-level skip（filled/maxlength/no-value/no-option）に対しては**設計上存在しない**。`src/dom/fill-plan.ts` の `BY_DESIGN_RESULTS`（78-81）が planner 警告を警告対象外と明記し、PBI-08の残存表示も真の実行失敗（missing-target/detached/error）専用。計装プローブ（button setStatus/showErrorのtitle記録・後にrevert）で、部分適用フローで `showError` が呼ばれないことを実ブラウザで確定。E2Eは「ガード動作＋設計どおりの沈黙」を回帰固定
- 残件（箱を開けたままにする理由）: 箱の文言は実ブラウザでの通知確認を求めており、通知自体がない現設計では満たせない。閉じるにはプロダクト判断が必要——(a) skipped-statusにも警告を出す（UX変更・要新PBI）、または (b) 箱・シナリオ文言を「開発者向け記録」側に寄せる修正。いずれも本PBIの自動チェック対象外
- 追記（2026-10-19・PBI-55で解消）: (a)(b)の二択ではなく第三の道（適用後プレビューに内訳表示＋ワンクリック報告）を実装。利用者への通知が実ブラウザE2Eで確認できたため本箱をチェックする。skipped-status自体の警告化は引き続き対象外（by-design維持）
