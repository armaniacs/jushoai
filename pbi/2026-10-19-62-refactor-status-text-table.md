# PBI: ステータス文言を1表に集約する

## ユーザーストーリー

開発者として、AIステータス→文言の対応を1表に持ちたい、なぜならバッジ・ガイドの2箇所並列実装は新ステータス追加のたびに同時編集を要求し、修正漏れが「ある画面だけ文言なし」になるため（失敗通知表は理由語彙でキー集合が異なるため対象外。詳細は実装記録）。

## 優先度

- 順位: 2位 / 4件
- RICEスコア: 16（Reach=6 / Impact=1 / Confidence=80% / Effort=0.3人月）
- 根拠: 波及コストの削減効果が大きい。文面差異は列で保つためUX不変。61とは独立。

## BDD受け入れシナリオ

```gherkin
Scenario: 新ステータスは1表の1行で足りる
  Given 新しいAIステータスが増える
  When 対応表に1行足す
  Then バッジ・ガイドの両方に文言が出て、漏れがコンパイルエラーになる（失敗通知表は別語彙のため対象外）

Scenario: 用途別の文面差異が保たれる
  Given 既存の全ステータスがある
  When 各画面の文言を見る
  Then 従来どおり用途別の文面が出る（共通化による画一化なし）
```

## 受け入れ基準

- [x] `STATUS_TEXT`（名称は同等でも可）がステータスをキー・badge/guideTitle文言を列に持つ1表として定義されること
- [x] `badgeLabel`・ガイドtitleが1表の薄い参照になること（失敗文言表は別語彙のため対象外）
- [x] キー漏れが型で検出されること（`Record<AiState, ...>`）
- [x] 文面のスナップショット的回帰（既存テスト＋目視差分なし）があること
- [x] 既存テストが緑維持

## テスト戦略

- 単体: 全AiState×2用途の文言が空でないことを固定する
- 回帰: badge/guide関連テスト＋`make check` green
