# PBI: ウィザード引き継ぎ（複数ページの再提示）

## ユーザーストーリー
複数ページの申込フォームを使う利用者として、入力→確認→完了の途中で値を引き継いで再提示してほしい、なぜならページが変わるたびに最初から入力し直すのは手間で、確認画面での訂正も面倒だから

## 優先度
- 順位: 6 / 8
- RICEスコア: 100（Reach=300 / Impact=2 / Confidence=50% / Effort=3人週）
- 根拠: 価値は大きいが確信度低・工数大（サイトごとに遷移が違う）。セッション内記憶に留め自動入力はしない

## BDD受け入れシナリオ
Scenario: 次ページで再提示される
  Given 1ページ目で承認・注入済みのセッション
  When 2ページ目でボタンを押す
  Then 前ページの値を引き継いだプレビューが出て承認後に注入される

Scenario: セッション終了で消える
  Given 引き継ぎ中のセッション
  When タブを閉じるか完了する
  Then 引き継ぎ値は破棄され保存・送信されない

## 受け入れ基準
- [x] ページ読み込み時の自動入力はしない（方針維持）。再提示＋承認のみ → 引き継ぎ値はプレビューの候補として出るだけで、注入は常に承認後（BDDシナリオ1「承認後に注入される」の契約は変えない）
- [x] 引き継ぎはセッション内・端末内のみで、永続保存・外部送信しない → 引き継ぎ値はcontent scriptのメモリ（タブスコープ）にだけ置く。タブを閉じると破棄され、storage・メッセージ・監査ログに交差しない（BDDシナリオ2をテスト方針で固定）
- [x] 確認画面の訂正はundo（132）と競合しない操作にする → undoは「直後の注入」の1ショット（ユーザーが追記した欄は触らない）で、引き継ぎは次ページのプレビュー候補として独立。プロファイル値は常に引き継ぎ値より優先

## 実装記録（2026-10-23）

- `src/core/carryover.ts`: 純粋層。`carryoverFor`（欄の署名→前ページの承認値。input のみ・select/radio は触らない）、`mergeCarryover`（適用済みの値をマージ。同じ署名は最新値）。
- `src/core/planner.ts`: `PlanContext.carryover`。プロファイル値が空の欄だけ引き継ぎ値にフォールバックする（profile値が常に優先）。
- `src/content-session.ts`: `SessionInput.carryover`（前ページの値）と`SessionEnv.recordCarryover`（適用後に注入した値をマージ）。
- `src/entrypoints/content.ts`: タブスコープの`carryover`マップを実行間で保持し、セッションへ渡す。適用後に注入した値をマージする。
- 引き継ぎの範囲: 欄の署名（name/htmlId）→値のペアのみ。プロファイル・住所の値は保存データから直接来るため重複しない。タブを閉じると消える（BDDシナリオ2）。
- テスト: `tests/core/carryover.test.ts`（4件）、`tests/core/planner.test.ts`に引き継ぎフォールバック・profile優先・select除外の3件追加。
