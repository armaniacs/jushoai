# PBI: ランタイムmessage規約にバージョン識別子を付ける

## ユーザーストーリー

開発者として、新旧混在時の形状ずれが「静かな劣化」として見逃される状態をなくしたい、なぜならAiRequestの形状変更時に送受信の世代ずれが型外で検出できず、誤分類や無応答として顕在化するため。

- 対象: src/messages.ts:33-52

## BDD受け入れシナリオ

```gherkin
Scenario: AiRequest全バリアントにv:1が付与される
  Given 送信側がAiRequestのいずれかのバリアントを送る
  When メッセージを構築するとき
  Then 全バリアントにバージョン識別子v:1が付与されている

Scenario: receiver側は未知版をwarnして安全側に倒す
  Given receiver側が未知のバージョン識別子を受け取った
  When メッセージを受信するとき
  Then warnを記録し、既知の形状として扱わず安全側に倒す
```

代替案: 上記のバージョン識別子の代わりに、送受信lockstep契約コメント＋互換テストで世代ずれを検出してもよい。
