# PBI: README冒頭に利用者向けと開発者向けの読み分けを足す

## ユーザーストーリー
README を開いた人として、自分がどこまで読めばよいか知りたい、なぜなら利用手順と開発手順が同居し読みどころが判断できないから

## 優先度
- 順位: 5 / 7
- RICEスコア: 30.0（Reach=6 / Impact=0.5 / Confidence=1.0 / Effort=0.1）
- 根拠: 新規の読み手に届く2行追加。事実変更なし

## 背景
- README に利用手順と `make` 開発手順が同居し、対象読者と前提知識の宣言がない
- 置き換え案（冒頭の説明直後に追加）: `使うだけなら「使い方」まで読めば足ります。開発に参加する人は「開発者向け」から読んでください。`

## BDD受け入れシナリオ
Scenario: 初めてREADMEを開く
  Given README を開いた
  When 冒頭を読む
  Then 自分の立場でどこまで読めばよいか分かる

Scenario: 既存の構成が壊れない
  Given 修正後の README である
  When 見出し構成を比べる
  Then 見出しの増減・順序変更がない

## 受け入れ基準
- [ ] 冒頭に読み分けの宣言がある
- [ ] 見出し構成が変わらない
- [ ] サイトビルドに影響しない（README はサイト生成の入力ではないことを確認する）

## テスト戦略
- E2E: なし（文書のみ）
- 統合: なし（文書のみ）
- 単体: なし（文書のみ。`tests/release-notes.test.ts` 等の README 参照テストがあれば通す）

0.5pt（要チームでの見積もり）
