# PBI: カナ判定の重複評価をなくして分類を速くする

## ユーザーストーリー

大規模フォームの利用者として、欄がたくさんあっても入力補助の表示がもたつかないでほしい、なぜなら数十〜数百欄のフォームでも快適に入力したいから。

開発者として、同じ欄へのカナ判定が何度も走らないでほしい、なぜなら不要な正規化と正規表現の評価が積み上がり CPU を無駄にするから。

## 優先度

- 優先度: 中（現状でも CPU 影響は微小でリリース可のため）
- 順位: 3位 / 12件
- RICE スコア: 250（Reach=100 / Impact=0.25 / Confidence=50% / Effort=0.05人月）
- 根拠: 分類が走るたびに効くが、1回あたりの効果は微小。依存なし
- 出典: plans/2026-10-15-2247-review-1014z.md の Tuning Low 指摘（kana判定の重複評価）
- 制約: 挙動不変のリファクタ。正規表現のテストが落ちたら期待値ではなく正規表現を直す

## BDD受け入れシナリオ

```gherkin
Scenario: 同じ欄を何度分類しても結果が変わらない
  Given カナ欄と漢字氏名欄が混ざったフォームがある
  When 分類を実行する
  Then 各欄の分類カテゴリとカナ種別は変更前とすべて一致する

Scenario: カナ欄が多いフォームでも分類が速くなる
  Given カナ語彙を含む欄を多数持つフォームがある
  When 分類を複数回実行して所要時間を比べる
  Then 分類結果は変わらず、重複していた判定の回数は欄あたり1回相当に減る

Scenario: プレースホルダだけがカナの欄も正しく扱われる
  Given プレースホルダにカナだけを書いた欄がある
  When 分類を実行する
  Then その欄は変更前と同じカナ分類になり、漢字氏名欄がカナ欄に誤って変わることはない
```

## 受け入れ基準

- [x] 同一フォームの分類結果（カテゴリ・信頼度・カナ種別）が変更前と1件も変わらない
- [x] 同一フィールドに対するカナ要否の判定が、1回の分類あたり欄単位で1回相当になる
- [x] 既存の分類・カナ関連テストがすべて緑のままである（期待値の書き換えなし）
- [x] 数十〜数百欄規模のフォームで分類の総処理量が減ることが確認できる

## テスト戦略

### E2Eテスト

- サンプルフォームを開いて分類からプレビュー表示まで行い、カナ欄の表示内容が変わらないことを目視する

### 統合テスト

- カナ欄・漢字欄混在のフォーム一式を `classifyAll` 相当で分類し、変更前後の結果スナップショットが一致する
- 大規模フォーム相当の欄数で分類を実行し、処理回数・所要時間が改善方向にあることを比べる

### 単体テスト

- カナ語彙・プレースホルダ・パターン属性の境界値ごとに、分類結果が変更前と一致する
- カナ要否が真・偽の両方で、重複評価が起きないこと（判定回数の計測）
- 結合濁点など正規化で見え方が変わる入力で、カナ種別の判定が変わらない
