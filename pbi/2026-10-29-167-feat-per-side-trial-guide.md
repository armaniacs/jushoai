# PBI: 片側欠落のガイドと0件エラーの試作誘導

## ユーザーストーリー
利用者として、住所だけ・名前だけが未登録のときも試作で埋めたい、なぜなら0件エラーのままでは次の一手がわからないから

## ビジネス価値
- 片側欠落状態の離脱削減と、エラーから試作への導線確保
- 測定: ガイド表示→有効保存に至る割合

## BDD受け入れシナリオ

```gherkin
Scenario: 住所だけないときは住所の試作が出る
  Given 有効な名前のみある状態
  When ガイドを見る
  Then 「架空の住所を作って試す」があり結合版はない

Scenario: 0件エラーから試作できる
  Given 住所0件で住所画面の保存を押す
  When 0件エラーの「架空の住所を作って試す」を押す
  Then 住所が作られて保存が成功する

Scenario: 名前側も対称
  Given 有効な住所のみある状態
  When ガイドを見る
  Then 「架空の名前を作って試す」がある
```

## 受け入れ基準
- [ ] ガイド表示はどちらか一側でも未有効なら出る
- [ ] 試作ボタンは両欠・名欠・住欠で切り替わる

## 実装者向け注記

### 現状コードの確認
```bash
grep -n "hasValidProfile\|trial-banner\|お試し入力" src/entrypoints/options/main.ts
```

確認済み（2026-10-29）: ガイドは有効名前0件でのみ表示、試作は結合のみ、0件エラーに誘導なし。

### 実装手順
1. `guideTrialMode` 純粋関数と単体テストを先に書く
2. 試作の側別充填を切り出し、単側試作は保存処理へ委譲する
3. ガイド文言の側別切替と0件エラーの試作アクションを付ける
4. E2Eを追加し `make check` で緑を確認する

### 落とし穴
- 保存ボタンは両ページ同名のため xpath を節に絞ること
- 試作保存は両側検証を通してから書くこと（未検証混入の再発防止）
