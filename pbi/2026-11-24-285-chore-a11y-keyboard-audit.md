# PBI: キーボードとスクリーンリーダーだけで一連の入力ができるかを監査する

## ユーザーストーリー
マウスを使わない利用者として、ボタンの起動からプレビューの承認、元に戻すまでをキーボードと読み上げだけで完了したい、なぜなら途中の 1 か所でも詰まると拡張全体が使えなくなるから

## 区分
改善 / 1.0 推奨

## 優先度
- 順位: 11 / 17
- RICEスコア: 17 (Reach=10 / Impact=2 / Confidence=50% / Effort=0.6人週)
- 根拠: 個別には対応済み（Alt+J、ボタンの矢印キー移動、ダイアログのフォーカストラップ、aria-live のバッジ）。ただし通しの監査記録が無い。台帳 `2026-10-31-00-backlog-next-cycle.md` の「キーボード操作」は「マウスを使えない利用者の需要が観測されたら最優先で再開」の宣言で、正式版は需要の観測を待たずに 1 回確認する節目と判断した

## BDD受け入れシナリオ

```gherkin
Scenario: キーボードだけでフォームを埋める
  Given フォームのあるページを開いている
  When  Tab でボタンに移動して Enter を押し、プレビューで行を確認して「入力する」を押す
  Then  欄が埋まり、結果画面で「元に戻す」にも Tab で届く

Scenario: 読み上げで件数と警告が分かる
  Given スクリーンリーダー (VoiceOver / NVDA) を使っている
  When  プレビューを開く
  Then  件数・警告・各行の欄名と値が読み上げられ、閉じるとフォーカスが元の位置に戻る
```

## 受け入れ基準
