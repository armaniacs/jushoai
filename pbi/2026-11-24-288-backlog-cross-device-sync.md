# PBI: 端末間でプロファイルを移しやすくする（同期は暗号化前提の任意機能）

## ユーザーストーリー
自宅と職場など複数の端末で使う利用者として、片方で登録したプロファイルをもう片方でも使いたい、なぜなら今は JSON を書き出してファイルを運び、読み込む手作業が要るから

## 区分
将来機能 / 1.0 後

## 優先度
- 順位: 14 / 17
- RICEスコア: 3 (Reach=20 / Impact=1 / Confidence=50% / Effort=3人週)
- 根拠: `chrome.storage.sync` は容量が小さく、内容がブラウザ提供元のアカウントに渡る。「プロファイルの値は外部に送信しない」という基本約束とぶつかるため、同期するなら 287 の暗号化が前提になる。まずは同期ではなく移行の手間を下げる案（QR や暗号化エクスポート）から比較する
- 着手条件: 287 の完了、または複数端末での利用要望が観測されたら

## BDD受け入れシナリオ

```gherkin

Scenario: 同期を選ばない利用者には何も変わらない
  Given 利用者が同期を有効にしていない
  When  拡張を使う
  Then  storage.sync には何も書かれない
```

## テスト戦略

- 統合: 同期無効時に sync を書かない
- 単体: 暗号化エクスポートの往復
