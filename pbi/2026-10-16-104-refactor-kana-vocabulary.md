# PBI: カナ語彙をトークン表1つ＋用途別2述語に一本化する

## ユーザーストーリー

開発者として、カナ語彙の追加時にlegend側の判断漏れをなくしたい。現状はKANA/KANA_HEADINGの二重リテラルで、片方の更新忘れがlegend誤爆か取りこぼしになるため。

## 優先度

- 順位: 2位 / 8件
- RICEスコア: 500（Reach=100 / Impact=0.5 / Confidence=80% / Effort=0.08人月）
- 根拠: 分類全体に効く構造是正。依存なし。
- 出典: architecture-review 候補1(Strong)

## BDD受け入れシナリオ

```gherkin
Scenario: 語彙追加が1箇所で両用途に反映される
  Given 新語彙トークンを表に追加する
  When 欄所有側とlegend側で判定する
  Then 両方に一貫して反映され、除外集合の手管理が要らない

Scenario: 分類結果が変わらない
  Given 既存の全分類テストがある
  When 語彙表に置き換える
  Then 結果が1件も変わらない（期待値書き換えなし）
```

## 受け入れ基準

- [x] 語彙がトークン表1つになる（正規表現リテラルの二重管理を解消）
- [x] Interfaceが `matchFieldOwned` / `matchLegend` 相当の2述語になる
- [x] 全既存分類・カナテストが期待値無変更で緑
- [x] 短い読みのlegend除外が表駆動で表現される

## テスト戦略

- E2E: サンプルフォーム相当でカナ分類の不変を確認する
- 統合: `classifyAll` 相当の前後一致を確認する
- 単体: 語彙表駆動の境界値（注意書き・正規legend・欄所有）を網羅する
