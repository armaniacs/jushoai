# PBI: フォームボタンのバッジエラー表示に aria-live 相当の通知手段を付与する

## ユーザーストーリー

スクリーンリーダーを利用するフォーム利用者として、同意ゲート失敗やAI失敗の理由がバッジに表示されたときに読み上げで知りたい。なぜなら現状はバッジのテキスト変化だけで伝達され、注入失敗に気づけないため。

## 優先度

- 順位: 2位 / 12件
- RICE スコア: 300（Reach=30 / Impact=1 / Confidence=50% / Effort=0.05人月）
- 根拠: H（dialog対応）の対になる a11y 残件でユーザー影響が大きい。依存なし

## BDD受け入れシナリオ

```gherkin
Scenario: 同意ゲート失敗がバッジに表示されたら読み上げられる
  Given スクリーンリーダーを利用してフォームを開いている
  When 同意ゲートに失敗しバッジにエラー理由が表示されたとき
  Then エラー理由がスクリーンリーダーで読み上げられる

Scenario: AI失敗の理由がバッジに表示されたら読み上げられる
  Given スクリーンリーダーを利用してフォームを開いている
  When AI処理に失敗しバッジにエラー理由が表示されたとき
  Then エラー理由がスクリーンリーダーで読み上げられる

Scenario: 通常のバッジ状態変化では不要な読み上げが起きない
  Given スクリーンリーダーを利用してフォームを開いている
  When エラーではない通常の状態表示にバッジが変わったとき
  Then 不要な割り込み読み上げは行われない
```

## 受け入れ基準

- [x] 同意ゲート失敗時にバッジに表示された理由がスクリーンリーダーに伝わること
- [x] AI失敗時にバッジに表示された理由がスクリーンリーダーに伝わること
- [x] 表示文言の変更がないこと
- [x] 見た目の変更がないこと
- [x] Shadow DOM（closed）内で有効に動作すること

## テスト戦略

- E2E相当: スクリーンリーダー利用を想定し、同意ゲート失敗時とAI失敗時にエラー理由が支援技術に通知されることをシナリオ単位で確認する
- 統合相当: ボタンのバッジ表示状態（通常表示→エラー表示→通常表示への復帰）の遷移ごとに、通知の有無が期待通りであることを確認する
- 単体相当: エラー表示時に通知手段が有効であり、通常表示時には不要な通知が有効にならないことを境界条件として確認する
