0.1.40 の後に正式版を出す前提で、プロジェクト全体を見直した。機能の充足、改善、将来機能、セキュリティ上の必須対応に分けて 17 件を PBI 化した（274-290）。採点の Reach は影響を受ける利用者の割合 (0-100) に揃えた。依存は採点より優先した。

## 機能充足の評価

結論: 利用者が必要とする中心機能はそろっている。正式版に足りないのは機能ではなく、正式版としての約束（脆弱性の窓口、保存データの互換性、配布経路の保護）。

| 利用者の要求 | 現状 | 判定 |

## セキュリティ観点で確認済みの良い点（PBI 化しない）

- 必須権限は `storage` と `contextMenus` だけで、host 権限は任意権限として保存時に要求
- background の `onMessage` は `sender.id` を検証。content 側はタブ宛ての dispatcher で型ガードと除外判定を一本化
- API キーは AES-GCM エンベロープで、復号は background だけ
- `validateBaseUrl` が https 限定・内部アドレス拒否、新しい接続先は DNS 解決後の IP を承認するまで送らない
- Actions は SHA 固定、release は `persist-credentials: false` と `npm ci --ignore-scripts`
- sources zip からスキャン成果物・`.env*` を除外

## やらないこと（宣言の継続）

- ショートカット起動、CSV 入出力: `2026-10-31-00-backlog-next-cycle.md` の宣言と再開条件を維持
- キーボード操作: 285 の監査結果で宣言を更新する
- クロスオリジン iframe、ページ読み込み時の自動入力、クレジットカード等の機微情報、英語 UI: README の「対応しないもの」と既存方針どおり。正式版でも変えない
