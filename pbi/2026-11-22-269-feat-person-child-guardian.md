# PBI: 児童と保護者を人物として分ける

## ユーザーストーリー
学校の申込み形を使う人として、児童と保護者の値を別々に置きたい、なぜなら いまは切替え用の profiles しかなく同時利用ができず、同名の緊急連絡先が混ざるから

## 優先度
- 順位: 4 / 6
- RICEスコア: 40 (Reach=40 / Impact=3 / Confidence=50% / Effort=1.5人週)
- 根拠: 足立対応の中心。語と区画の併用、確信度での決定、二択表示を深掘りで確定済み。依存は 266 のみ

## BDD受け入れシナリオ

```gherkin
Scenario: 役割が分かれる
  Given 児童と保護者に同じ名の欄が並ぶ
  When  分類する
  Then  児童側は児童、保護者側は保護者に寄る

Scenario: 値を別々に計画する
  Given 児童の人物と保護者の人物を選ぶ
  When  計画を作る
  Then  児童氏名は児童から、保護者氏名は保護者から引く
```

- [x] `Item` に役割が乗り同一役割内でのみ分割と絞り込みが働く
- [x] 衝突時は確信度で決め根拠が残る
- [ ] 旧 profiles は本人として移る
- [x] プレビューで児童と保護者を別々に選べる
- [x] `make check` が緑

## テスト戦略

- 統合: 足立 fixture で児童と保護者の混線が無い事
- 単体: 役割判定と移行処理の境界値

## 出どころ
- `dig-findings.md` の決定1から3 と `src/core/types.ts` の Profile 形
- 3 人目が出たら選び直せる余地を残す方針

## 実装記録
- プレビューに児童用・保護者用の2つの選択欄と用途表示を追加。表示条件は児童と保護者の両方の行がありプロファイルが2件以上のとき(src/ui/preview.ts の hasRoleSelect)で、単一プロファイルや役割が1種のフォームは従来どおり1つの選択欄
- 既定の割当ては児童と本人=1件目、保護者=2件目。選択欄を変えるとその役割の行だけ再計画し、住所は従来どおり共通の1つ。選択欄を出さないフォームでは既定割当てを空に戻して既定経路を変えない
- 選択欄の現在値は行に載っている実際に使われたプロファイル id から取るため、解決できない id が残っていても表示は行に合わせる
