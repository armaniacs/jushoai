# PBI: 部分適用の内訳を適用後プレビューから報告できるようにする

## 背景

PBI-82の開発者ストーリー（適用できなかった内訳を数えて発生率を把握する）は、件数集計（`FillSummary.byResult`）の実装と単体・E2Eの動作確認までは済んだが、集計を開発者に届ける導線がない。既存の「開発に報告」チェックは適用時プレビューでのみ出せて、本文も「初回NG→AI分析OK」用で内訳を含まない。部分適用バナーのクリックは再適用導線のため、内訳報告のワンクリック化は未実現。

## ユーザーストーリー

開発者として、部分適用が起きたときに適用後プレビューから内訳入りのGitHub issueをワンクリックで開きたい、なぜなら内訳の件数集約がなければ発生率を把握して改善につなげられないため。

## 優先度

- 順位: 1位 / 1件
- RICEスコア: —（単一件のため採点なし。PBI-82の開発者ストーリーの直接の続き）
- 根拠: 82の残件（BDD箱）を閉じるための選定手段（1b＋内訳のみ）。既存の報告URL組み立て・プレビュー・適用フローの延長で、振る舞い変更は適用後プレビューの残置のみ。

## BDD受け入れシナリオ

```gherkin
Scenario: 部分適用後に内訳報告を開ける
  Given 一部の欄が適用されなかった適用実行がある
  When 適用後のプレビューを見る
  Then 内訳（適用済み・見送り・失敗の件数と理由別内訳）が表示され、
    「内訳をissueで報告」ボタンが1つある

Scenario: 報告ボタンで内訳入りのissueが開く
  Given 内訳表示のある適用後プレビューがある
  When 「内訳をissueで報告」を押す
  Then 件数内訳入りのGitHub issue下書き（title・body・labels）が新規タブで開く

Scenario: 全部適用できたときは従来どおり閉じる
  Given すべての欄が適用できた適用実行がある
  When 適用が終わる
  Then プレビューは従来どおり閉じ、報告ボタンは出ない
```

## 受け入れ基準

- [x] 部分適用時（filled < total）にプレビューが閉じず、内訳表示＋報告ボタン＋閉じるボタンになること（真の失敗バナーは従来どおりボタンにも出る）
- [x] 全部適用時（filled == total）は従来どおりプレビューが閉じること
- [x] 報告URLのbodyが件数内訳のみ＋最小文脈（page・provider・version）で、プロファイル値・分類スナップショット・欄メタデータを含まないこと
- [x] 実ブラウザE2Eで、部分適用後に内訳表示と報告ボタンが出ることが確認できること
- [x] 既存テストが緑維持

## テスト戦略

- 単体: `buildPartialIssueUrl` のtitle・body・labelsとPII不含を固定する
- 単体: `showResult` の内訳表示と報告ボタンのコールバックをjsdomで固定する
- E2E: 部分適用fixtureで適用後に内訳表示＋報告ボタンが出ることを実ブラウザで確認する（外部遷移のクリックまでは踏まない）
- 回帰: `make check` green
