# ドキュメントサイト 設計書

JushoAI の公開ドキュメントサイト（GitHub Pages）。雰囲気は yasumaro のサイト（`https://armaniacs.github.io/yasumaro/`）に倣い、日本語と英語の 2 言語で、ランディングと利用者向けガイドを提供する。

## 目的とスコープ

- 利用者が JushoAI の価値、導入、AI プロバイダの設定、プライバシーの扱いを理解できるようにする
- 事実の出どころは README、設計書、コードに限る。未確認の挙動は「ブラウザによっては」のように正直に書く

### 含める

- ランディングページ、ガイド 5 本、ガイド一覧（日本語と英語）
- 提供済みのロゴ画像を使った見た目（ファビコン用の縮小版を含む）
- HTML/CSS で再現した画面モック
- Markdown から静的 HTML を生成するビルドスクリプトと、そのテスト
- GitHub Pages へのデプロイワークフロー（ファイルの用意のみ）

### 含めない

- 開発者向けドキュメント（アーキテクチャ、分類ルールの仕様、拡張ポイント）
- 実機のスクリーンショット
- リポジトリの作成、push、Pages の有効化（利用者側の作業）
- ブラウザの言語による自動切替、検索機能
- 拡張機能本体へのアイコン設定

## 構成

```
site/
  build.mjs            Markdown と HTML テンプレートから静的 HTML を生成する
  templates/           共通レイアウト（ナビ、フッター、言語切替）
  content/ja/*.md      ガイドの本文（日本語）
  content/en/*.md      ガイドの本文（英語）
  i18n/{ja,en}.json    ランディングの文言
  assets/              CSS、ロゴ、ファビコン、画面モックの部品
site-dist/             生成物（git 管理外）
```

- ビルドは Node のスクリプト 1 本。依存は Markdown 変換（`markdown-it`）と front matter の読み取りだけで、フレームワークは使わない
- `make site` でビルドし、`make site-serve` でローカルプレビューする
- 日本語がルート（`/`）、英語は `/en/` 配下。どちらもディレクトリ形式（`/guides/ai-providers/`）
- 言語切替は、対応するページへのリンクで行う（JS 不要）。各ページに `hreflang` を付ける
- ベース URL は環境変数 `SITE_BASE`（既定 `/`）で受け、リポジトリ名のパス（例 `/JushoAI/`）にも対応する

## ページ

| URL | 内容 |
|---|---|
| `/` | ランディング |
| `/guides/` | ガイドの一覧 |
| `/guides/getting-started/` | はじめに（インストール、初回登録、基本の使い方） |
| `/guides/ai-providers/` | AI プロバイダの設定 |
| `/guides/privacy/` | プライバシーと送信データ |
| `/guides/how-it-works/` | 対応するフォームと仕組み |
| `/guides/troubleshooting/` | トラブルシューティングと FAQ |

英語は同じ構成で `/en/` 配下に置く。

### ランディング

1. ヒーロー: 日本式フォームの氏名・フリガナ・住所を、正しい欄に、正しい形で入れる。「JushoAI で入力」ボタンの画面モックを添える
2. 特徴: 分割欄への対応、ルール主体 + AI 補助、プレビューで確認してから入力、プロファイルの値は外に出さない
3. 仕組み（4 ステップ）: 登録、ボタン、プレビュー、入力
4. 対応する欄: 氏名の分割、カナ 3 種（全角カナ・ひらがな・半角カナ）、住所の 2〜4 分割、電話・郵便番号、都道府県のプルダウン
5. AI プロバイダ: OpenAI 互換（OpenAI / Groq / Mistral / Ollama / LM Studio）、Gemini、ブラウザ内蔵 AI。初期状態は「使わない」
6. プライバシー: 送るのは欄のメタデータだけ、API キーは暗号化、クリックしたときだけ通信
7. インストール: ストアには公開していないため、ソースからビルドして `dist/chrome-mv3` を読み込む手順（`make install`、`make build`）
8. FAQ

### ガイド

- はじめに: インストール、プロファイルと住所の登録、ボタンとプレビュー、住所を複数登録する場合
- AI プロバイダ: プロバイダごとの設定、権限の確認、接続テスト、バッジの見方、Ollama の `OLLAMA_ORIGINS`、内蔵 AI のフラグ（Chrome と Edge）
- プライバシー: 送る内容と送らない内容、キーの保管と限界、通信が起きる条件、ページ上の文言が含まれうること
- 仕組み: ルール分類、AI の役割（分類だけ）、値の整形（カナ変換、電話・郵便番号のハイフン判定、住所の結合）、入力済みの欄は上書きしないこと
- トラブルシューティング: バッジごとの原因と対処、よくある質問

## 見た目

- ダークテーマを基本とし、`prefers-color-scheme` でライトテーマにも対応する。ナビは上部に固定し、すりガラス風の背景にする。丸角のカードとヒーローのグラデーションは yasumaro に倣う
- 配色はロゴに合わせて、白・黒・珊瑚色（`#ff5757`）を基調にする。アクセントは珊瑚色
- ロゴは `~/Downloads/JushoAI_512-512.png`（黒の「住」に珊瑚色の「JushoAI」。背景は白で不透明）を `site/assets/` にコピーして使う。ダークテーマでは白い角丸のタイルに載せる。ファビコン用の縮小版（32px、180px）はこの画像から作る
- 画面モックは HTML/CSS で再現する: 入力ボタンとバッジ、プレビュー（欄と値の一覧、AI 判定の印）、AI のガイドパネル、分割欄のフォームに値が入る前後
- コードブロックにはコピーボタンを付ける。フォントはシステムフォントで、外部リソースは読み込まない

## 多言語

- ランディングの文言は `i18n/{ja,en}.json`、ガイドは `content/{ja,en}/*.md`
- ビルド時に、キーまたはファイルの過不足があれば失敗させる（日英の内容のずれを防ぐ）

## デプロイ

- `.github/workflows/pages.yml` を用意する。`site/**` と、ガイドが参照するファイルの変更で起動し、`npm ci`、`npm run site`、artifact のアップロード、Pages へのデプロイの順に実行する
- アクションはコミットのハッシュに固定する
- GitHub 側で、リポジトリの作成と Pages の有効化（Source: GitHub Actions）が必要。リポジトリ名のパス配下で公開する場合は `SITE_BASE` を設定する

## 品質

- ビルドスクリプトの単体テスト: Markdown の変換、front matter、日英のキーの対応、内部リンクの検証、`SITE_BASE` の付与
- 生成物のリンク切れと、ページごとの `title` と `description` の有無を検査する。これは `make site` に含める
- アクセシビリティ: 見出しの階層、コントラスト、キーボード操作、`lang` 属性、画像の代替テキストを守る
- 実機での見え方（スマホ幅を含む）は、`make site-serve` で人が確認する
