# フローティング通知と初回ガイド 設計書

設定画面の保存結果が見逃される問題と、初回利用者の導線不足を解消する。保存分離・お試し入力の基本設計は `2026-10-28-options-save-trial-design.md` に従い、この文書は浮動化と即時登録の変更点だけを定める。PBI-162 の「自動保存なし」条項は本設計が上書きする。

## 目的とスコープ

- 保存成功・保存エラー・試し入力結果を画面下部の inline から画面上部の浮動表示に移し、見逃しをなくす
- 初回ガイドを浮動化し、「試す」「名前を登録する」「住所を登録する」の次行動へ直接誘導する
- お試しボタンは生成＋即時登録まで行い、保存ボタン操作を不要にする

### 含める

- `#float-root`（画面上部固定・前面）の新設とガイド枠＋通知枠の2スロット管理
- 成功トースト（4秒で自動消去）、エラー固定バナー（×か次の通知まで残留）、初回ガイド（×で一時非表示）
- ガイド3ボタンと文言確定、成功トーストの個人名入り文面（純粋関数化）
- プロファイル／住所ページの通知の浮動への移行、E2E・単体の更新

### 含めない

- AI・除外・対応付け・監査・転記セクションの inline 通知の変更
- ブラウザ Notification API の使用
- エラー切り詰め規則の変更（5件＋他N件を維持）
- 分類・注入・承認フローの変更

## 現状と原因

- 保存結果は `#app` 末尾の inline（`p.saved` 緑文字／`ul.errors` 赤リスト）で、スクロール位置によっては視界に入らず見逃される
- お試し入力は成功表示だけで保存は手作業だったため、0件状態との組み合わせで導線破綻を起こした（PBI-162 追補で0件生成は解消済み）
- 初回案内はページ先頭の inline（無スタイルの `.trial-banner`）で、スクロールで消えるうえ正常系への誘導がない

## アーキテクチャ

```
render() ──通知イベント──▶ #float-root（main.ts が1回だけ構築）
                             ├─ 通知枠：成功トースト／エラー固定バナー（同種は置換）
                             └─ ガイド枠：初回条件の間だけ表示
```

- 浮動層は DOM 構築のみで chrome API に触れない。`notice()`（`dom.ts`）は他セクション用に残し、文言切り詰め規則を共有する
- 優先順位はエラー＞ガイド＞成功。ガイド枠と通知枠は独立スロットとして共存する
- 成功タイマーは新通知でリセットする

## UI

### 通知枠

- 成功トースト：4秒で自動消去、aria-live polite。保存成功・試し登録成功が対象
- エラー固定バナー：×ボタンか次の通知まで残留、role=alert、切り詰めは現行維持
- 保存後のタブ誘導ボタン（住所を入力する等）は通知枠内のアクションとして同居させる

### ガイド枠

- 表示条件：有効プロファイル0件かつ表示タブがプロファイル／住所。×はセッション内非表示（メモリ旗、再読み込みで復活）
- 見出しは現行維持「初めてですか？架空の名前と住所で試せます」
- ボタン3種（いずれもタブ移動以外に副作用なし、試しボタンを除く）：
  - 「架空の名前と住所を作って試す」→ 生成＋即時登録
  - 「名前を登録する」→ プロファイルタブへ移動
  - 「住所を登録する」→ 住所タブへ移動
- 旧 inline `.trial-banner` 配置は廃止し浮動ガイド枠へ一本化する

### 即時登録フロー

試しボタン押下時の手順：空白カード確保（0件なら各1件作成）→ 空欄充填（入力済み不変）→ 両側を正規化・検証 → 成功なら `saveData` して成功トースト、失敗なら浮動エラーに項目表示（上書きなし）。両側とも検証を通してから保存するため、I1 で問題になった未検証混入は起きない。

成功トースト文は純粋関数 `trialToastText(profile, address)` が組み立てる：

`架空の名前として{姓} {名}さん（{都道府県}{市区町村}在住）を作りました`

例：`架空の名前として山田 太郎さん（東京都千代田区在住）を作りました`。挿入は必ず `textContent` で行う。
