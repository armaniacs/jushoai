# PR・普及強化の設計（広域スキャン第1領域）

日付: 2026-10-30

## 背景

JushoAI は Chrome ウェブストア・Edge Add-ons・Firefox AMO の3ストアに公開済みだが、ユーザーはほぼいない普及初期の段階にある。プロモーション動画（約2分）は完成し YouTube に公開済みで、ドキュメントサイトのランディングに埋め込み済み。一方で、GitHub の README には画像や動画が一切なく、ブログ記事の画像参照が1本壊れており、ストアの新着情報やレビュー対応の運用型が整備されていない。

広域スキャン（プロダクト機能・PR・開発プロセスの3領域）を行い、普及初期では PR の Reach が最大であるため、PR・普及領域を最初のサイクルとする。残る2領域（プロダクト機能・開発プロセス）は後続サイクルで別の設計書にする。

## 目的

- 初見の訪問者に「1クリックで入力できる」ことを即座に伝える（README と GitHub Pages の両面）
- ストア掲載情報を 0.1.29 以降の新 UI に追いつかせる
- リリースごとの周知とストアレビュー対応を運用型として仕組み化する

## スコープ

含めるもの（優先度順）:

1. **README と GitHub Pages にデモ GIF を埋め込む**
2. **ストアスクリーンショットを新 UI で更新する**
3. **「値を送らない」設計の記事を執筆する**
4. **リリース新着情報の運用型を作る**
5. **ストアレビュー対策の案内を足す**
6. **X 投稿のテンプレート型を足す**

含めないもの:

- プロダクト機能の拡張（ショートカット・コンテキストメニュー・CSV入出力など）は後続サイクルの設計書
- 開発プロセス（PR テンプレート・E2E 環境の安定化・CI への E2E 組み込み）は後続サイクルの設計書
- iframe 対応（PBI-123 として backlog 済み）
- 動画の作り直し（完成済み・公開済みのため触らない）

## 設計

### 1. デモ GIF（README と GitHub Pages の両面）

- 録画は `video/playwright/record.mjs` の仕組みを流用する。samples を自前配信（127.0.0.1:4181）で出すため別ターミナルは不要。README 用には約2分の promo.mp4 から切り出すのではなく、入力からプレビュー承認までの1シーンを 1280x800 で短く録画し直す（鮮明で小さくなる）
- 変換は ffmpeg の2段変換（palettegen でパレットを作り paletteuse で書き出す）。目標は 10〜20 秒・約3MB
- 配置は `site/assets/demo.gif` の1枚のみにする。landing の `#demo` セクションで動画の下に GIF を見せる（動画はクリックが必要、GIF は自動再生の即時プレビューという役割分担）。README からは公開 URL（`https://armaniacs.github.io/jushoai/assets/demo.gif`）で参照する。1枚で両面を満たし、`site/**` の変更なので `pages.yml` が自動デプロイする
- README 冒頭（最初の段落の直後）に GIF と動画へのリンクを置く。英語 README（README.en.md）にも同じ GIF を置く（UI が日本語専用である旨の note は既存）
- landing の文言は `site/i18n` の日英に追加する（日英対応検査・H2 数検査が `make site` で走る）

### 2. ストアスクリーンショットの更新

- `docs/store-listing.md` の 5枚構成（1280x800、最大5枚）を、0.1.29 以降の新 UI（フローティングガイド・保存分離・ナビ件数バッジ）を写した撮り直しに更新する
- 撮り方は現行どおり `samples/demo-registration.html` と設定ページを使い、ダミーのプロファイルで個人情報を写さない
- 画像のファイルはストア申請用としてリポジトリに含めない現行規則を維持する
- `docs/blog/images/` が空で、3記事が同じ `before-reanalyze.png` / `after-reanalyze.png` を参照しているが、画像は一度もコミットされていない。「再分析前」の状態（tel 3欄が単体扱いで maxlength 警告が3連）は、分類の2段階化（兄弟欄の補正で電話3欄を tel1/2/3 に束ねる）で修正済みのバグであり、現在のコードでは再現できない。再現のためにバグを戻すことはしないので、3記事から壊れた画像参照を削る

### 3. 「値を送らない」設計の記事

- `docs/blog/` の型（front matter + 画像）に沿い、`site/content/ja/privacy.md` と `site/content/ja/safety.md` を素材に、プロファイルの値を外部に送らない設計と通信の監査ログを解説する記事を書く
- Zenn 向けに整え、記事からドキュメントサイトの privacy・safety ガイドへリンクする
- 差別化の軸は「AI を使う設定にした場合でも送られるのは欄のメタデータだけで、プロファイルの値は送らない」という点

### 4. リリース新着情報の運用型

- `docs/store-listing.md` に「新着情報」の節を追加する。CHANGELOG の Added/Fixed から、ストアの「新着情報」欄に貼るユーザー向け文面を作るルールを書く（技術用語を落とし、利用者が得る変化を1行ずつ書く）
- `promo/x-post.md` の型を流用した、リリース告知の X 投稿テンプレートを同じ節に置く
- 次回リリースからこの型を使い、CHANGELOG・ストア・X の3面を1回の作業で周知できるようにする

### 5. ストアレビュー対策

- ストアレビューには返信できないため、説明文に「不具合・要望は GitHub の Issue へ」の案内を追記する。`docs/store-listing.md` の説明欄に1行を足す形
- Issue テンプレート（bug-report・feature-request・form-support）が既にあるため、案内はストアから Issue への誘導だけに絞る

### 6. X 投稿のテンプレート型

- `promo/` に機能紹介投稿のテンプレート型を追加する（1機能・1 GIF・1リンクの構成）。デモ GIF ができあがれば流用できる

## 実装の流れ

1. デモ GIF の録画と変換（`site/assets/demo.gif`）
2. landing への GIF 埋め込みと `site/i18n` の文言追加、README（日英）への GIF と動画リンク追加
3. ストアスクリーンショットの撮り直しと `docs/store-listing.md` の更新、blog 1本目の画像修復
4. 記事の執筆（`docs/blog/`）
5. 新着情報の運用型とストアレビュー対策、X 投稿テンプレートの追加（`docs/store-listing.md` と `promo/`）
6. `make site` で検証し、main に push して `pages.yml` の自動デプロイ後、公開 URL で確認

## 検証

- `make site` が緑であること（日英のキー対応・H2 数検査を含む）
- 新規・変更の Markdown は docs-charset 規約（CP932 で表現できる文字のみ）に適合すること
- GIF はファイルサイズ（約3MB 目標）と再生時間（10〜20秒）を確認すること
- README の画像参照が GitHub 上で表示されること、`pages.yml` のデプロイ後にランディングの GIF が表示されること

## 残る領域（後続サイクル）

- プロダクト機能: ショートカット起動、コンテキストメニュー、プレビューでのプロファイル切替、CSV入出力、キーボード操作、ダークモード
- 開発プロセス: PR テンプレート、E2E 環境の安定化（ChromeDriver と Chrome の版数整合）、CI への E2E 組み込み、samples corpus の拡充
