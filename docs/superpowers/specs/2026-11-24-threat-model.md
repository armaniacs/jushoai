# 脅威モデルと端末保存データ (PBI-280)

PBI-280 の受け入れ基準 1 件目 (設計書の表) の置き場所。利用者向けの説明はサイトの `privacy.md` (日英) にある。ここは保守者向けに、資産・攻撃者・信頼境界・対策・受容した限界を 1 か所にまとめる。書く内容はコードにある事実だけにする。将来構想や未実装の対策は書かない。

## 信頼境界

- 信頼する側: 拡張機能のコード (content script、Service Worker の background、設定ページ)。いずれも同じパッケージに同梱し、リモートコードは使わない (`docs/store-listing.md` の「リモートコードの使用」)。
- 信頼しない側: ページのスクリプトとページ上の文言、AI プロバイダの応答、利用者が設定した接続先の先にあるもの。
- 前提: `chrome.storage.local` の中身と IndexedDB の中身は、同じ OS アカウントの他の利用者と端末のマルウェアからは読めるものとして扱う。API キーの暗号化は、ストレージだけが流出した場合の緩和であり、同じ端末で動くものからの保護ではない (`README.md` の「送信されるデータ」)。

## 資産の一覧

保存場所・暗号化の有無・保持期間・消し方は、サイトの privacy ガイドと一致させること。コードの一次情報は `src/storage.ts`、`src/mapping-store.ts`、`src/approval-store.ts`、`src/assignment-store.ts`、`src/ai/audit-log.ts`、`src/ai/secret-store.ts`、`src/ai/settings-store.ts`。

| 資産 | 保存場所 | 暗号化 | 保持期間 | 消し方 | 外部送信 |
|---|---|---|---|---|---|
| プロファイル・住所 | `chrome.storage.local` (キー `jushoai:data`)。登録した個人情報 | なし (平文) | 削除するまで残る | 設定ページで「このプロファイルを削除」「この住所を削除」 | なし。値は AI にも送らない |
| 覚えた対応付け | `chrome.storage.local` (キー `jushoai:field-mappings`)。ドメインと欄の特徴 (`name` / `id`) から分類名への対応のみ。プロファイル値なし | なし (平文) | 最大 500 件。超えると古いものから削除 | 設定ページの一覧から削除 | なし。教えた欄は AI の送信対象から除外する |
| 短縮プレビュー用の承認記録 | `chrome.storage.local` (キー `jushoai:site-approvals`)。承認内容のハッシュ値と選択 ID のみ (最大 100 サイト)。元の値やラベル文字列なし | なし (平文) | 最大 100 サイト。超えると古いものから削除 | 上限超過時の自動削除のみ | なし |
| サイトごとのプロファイル候補 | `chrome.storage.local` (キー `jushoai:site-profile-assignments`)。ホスト名からプロファイル ID への対応のみ (最大 100 サイト)。プロファイル値なし | なし (平文) | 最大 100 サイト。超えると古いものから削除 | 上限超過時の自動削除のみ | なし |
| 監査ログ | `chrome.storage.local` (キー `jushoai:audit-log`)。送った欄のメタデータとモデルの応答。例は下記 | なし (平文) | 7 日間。期限切れは自動削除。上限は 1,000 件または合計 4,000,000 バイト (UTF-8) で、超えると古いものから削除 | 設定ページの「ログを削除」。AI を使わない設定では増えない | なし (端末内の記録)。TSV ダウンロードは利用者の操作でのみ端末外に出る |
| API キー | `chrome.storage.local` (キー `jushoai:ai-settings`) に AES-GCM のエンベロープで保存。復号の鍵は取り出せない形で別の保管場所 (IndexedDB、`jushoai-keys`) に置く | あり (AES-GCM)。ただし拡張機能自身のコードからは読み出せる | 置き換え・削除するまで残る。接続先のオリジンを変えると保存済みのキーは破棄する | 設定ページで「保存済みの API キーを削除する」にチェックして保存 | あり。使う設定のときだけ、認証のために利用者が選んだプロバイダへ送る。開発者のサーバーへは送らない |
| 一時メモリ (`元に戻す`・`ゲストで入力`・複数ページ引継ぎ) | タブのメモリ内のみ。ストレージにも監査ログにも保存しない | 該当なし (保存しない) | タブを閉じると消える | タブを閉じる | なし |

## 監査ログの記録例 (架空の値)

`request` は送ったプロンプトの全文 (欄のメタデータだけ)、`response` はモデルの応答 (先頭 2,000 文字、超えると末尾に `…`)。下記は形の例で、実在の個人情報ではない。

- `request` の例: `次の入力欄を分類し、... [{"id":"jai-3","name":"sei","htmlId":"","label":"お名前（セイ）","placeholder":"例：ヤマダ","nearby":"会員登録","type":"text","maxLength":20}]`
- `response` の例: `{"jai-3": "lastNameKana"}`
- `page_url` の例: `https://example.com` (オリジンのみ。パス・クエリ・フラグメントは含まない)

ページ由来の `label`・見出しなどには、ページに表示されていた個人情報が含まれることがある。その場合、送った内容と応答の記録にもその文言が残る。記録の扱いは利用者の責任で行う (TSV ダウンロード時も同じ)。

## 攻撃者別の対策と受容した限界

| 攻撃者 | 対策 | 受容した限界 |
|---|---|---|
| 悪意あるページ | 拡張機能の画面は閉じた Shadow DOM の中に置き、ページ側のスクリプトからは操作できない。ページ由来の文字列は HTML として解釈せず文字としてだけ表示する。入力はプレビュー承認のあとだけ行う。別オリジンの iframe の中のフォームには入力しない。AI に送る前には送信内容の確認パネルを開き、個人情報らしき文言の欄は既定で「送らない」にする | ページ上の文言 (`label` など) が AI への送信内容に含まれることがある。送信前パネルで内容を確認できる。入力したあとの値はそのページが読める (入力が目的のため)。ブラウザ本体の脆弱性は対象外 |
| 悪意ある AI 応答 | AI は欄の分類だけを行い、入れる値は作らない。分割・カナ変換・半角化・ハイフン判定は決まった処理で行い、プロファイルの値は AI に渡さない。応答の解析 (`parseLlmOutput`) は分類名の一覧にある文字列だけを採用し、それ以外は無視する。分類結果はプレビューで利用者が確認し、承認するまで入力しない。AI の呼び出しは Service Worker から行い、content script はメッセージ経由で結果だけを受け取る | モデルの応答の正しさは保証しない。誤分類は起こりうるが、プレビュー承認なしに入力しないことで影響を止める |
| 同じ端末の他の利用者 | API キーだけは AES-GCM で暗号化し、鍵をストレージとは別の保管場所 (IndexedDB) に取り出せない形で置く | プロファイル・住所・覚えた対応付け・承認記録・候補・監査ログは平文であり、同じ OS アカウントの他人からは読める。暗号化した API キーも、拡張機能自身のコードからは読み出せる。これらは設計上の既知の限界として脆弱性としては扱わない (`SECURITY.md` の「対象外の例」) |
| 端末のマルウェア | API キーの鍵をストレージと分離する。ストレージだけが流出しても鍵なしでは復号できない | マルウェアによる保存データの読み出しは対象外。端末上で拡張機能のコードとして動くものは、API キーを含め読み出せるものとして扱う (`SECURITY.md` の「対象外の例」) |
| 配布経路の侵害 | リモートコードを使わず、すべてのコードを拡張機能のパッケージに同梱する。配布は各ストア経由で、ソースコードは GitHub で公開している (GPL) | 利用者自身が設定した接続先 (Ollama など) 側の脆弱性は対象外。ブラウザ本体の脆弱性は対象外 (`SECURITY.md` の「対象外の例」) |

## ストア開示との対応 (2026-11-24 時点の確認結果)

一次情報は `docs/store-listing.md` の「データ使用の申告」。Chrome の「データの使用」の申告 (個人を特定できる情報はチェックしない、認証に関する情報とウェブサイトのコンテンツは AI を使う設定のときだけチェック) と、Firefox の `data_collection_permissions` (必須 `none`、任意 `websiteContent`) の宣言は、この文書の資産表および privacy ガイドの記述と一致する。不一致はないため文書側の修正は不要。ストア側の変更が必要な作業もない。

参照コード: `wxt.config.ts` (manifest 宣言)、`src/ai/permissions.ts` (Firefox の `websiteContent` 同意)、`tests/build/firefox-manifest.build.ts` (manifest 検査)。
