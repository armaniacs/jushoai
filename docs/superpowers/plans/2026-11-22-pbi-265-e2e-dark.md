# 実装計画: PBI-265 dark 配色回帰を e2e で守る (OS 切替なしの dark セッション) (2026-11-22)

## 背景と目的

PBI: `pbi/2026-11-22-265-chore-e2e-dark-colorscheme.md` (RICE 19)。PBI-209 の残 2 チェック (floating banner dark 追従・WCAG AA 4.5:1 実測) は OS 切替の手動確認で止まっているが、既存 harness の資産で OS 切替なしに自動化できる:

- **chrome-flags.ts:26** が `--force-prefers-color-scheme=light` を押している (PBI-162 の light assert 保護・理由コメントあり) — dark はその対称面
- **firefox**: harness.ts:66-67 が `setPreference('layout.css.prefers-color-scheme.content-override', 1)` を設定し「light token を assert するため」と記録 — **1 = light は実コードで実証済み、dark は 0**
- **closed-shadow read seam** (harness.ts:426-480) が shadow 内の全読み取りを単一所有 — 色の読み取りは seam で要素取得 → executeScript で getComputedStyle
- **scenarios.ts:396** に light rgba 厳密 assert の前例
- e2e ランナー: `test:e2e:chrome` = `vitest run -c vitest.e2e.config.ts chrome` (パス部分一致フィルタ)。新規ファイル `chrome.dark.e2e.ts` / `firefox.dark.e2e.ts` は include (`tests/e2e/**/*.e2e.ts`) とフィルタの両方に自動一致するため Makefile・script の変更は不要
- 単体テストは通常 config (`tests/**/*.test.ts`) で走るため `tests/e2e/contrast.test.ts` に置ける (純粋関数)

## Global Constraints (全タスクに適用)

1. **既存 light pin は無変更**: chrome-flags.test.ts の既存 pin・scenarios.ts:396 の rgba assert・既存シナリオ群は 1 文字も変えない (dark は追加のみ)。
2. **挙動不変**: プロダクトコード (src/) には触れない。変更は tests/e2e/ に限定。
3. **コメント・識別子は英語**・非自明な WHY のみ・タスク ID を書かない。
4. **コミット規約**: Conventional Commits 日本語・ファイル個別 add・push しない。
5. **完了条件**: `make check` 緑 + `npm run test:e2e:chrome` / `test:e2e:firefox` (HEADLESS=1) で dark シナリオを含む全 e2e が緑。CI (check.yml の e2e ジョブ) でも確認。
6. Firefox pref 値: light=1 (実コードで実証済み) / dark=0 — dark 強化セッションでバナー色が変わることを目視 (assert の成否) と両面で確認してから固定する。

## Task 1: dark セッション基盤

1. chrome-flags.ts: `chromeLaunchArgs(env, opts?: { scheme?: 'light' | 'dark' })` に拡張 (既定 light — 既存呼び出し `chromeLaunchArgs(process.env)` は無変更で light を維持)。dark 時は `--force-prefers-color-scheme=dark` を push (=light 行は分岐へ)
2. chrome-flags.test.ts: 既存 light pin は無変更 + dark バリアントの pin を追加 (HEADLESS 有無・CI 有無の組合せで 2-3 件)
3. harness.ts: `buildSession` (firefox) と `startChromeDriver` (chrome) に scheme パラメータを追加。firefox は pref 値を light=1 / dark=0 で分岐 (既存コメントの light 根拠を英語で維持・dark 側に WHY を追記)。既定は light (既存呼び出し互換)
4. adapter.ts: ChromeAdapter / FirefoxAdapter に colorScheme を渡す経路を追加 (constructor opts か start 引数 — 既存構造に合わせて選び report に記録)
5. focused: chrome-flags.test.ts + typecheck

## Task 2: dark シナリオ + エントリファイル + PBI-209 閉鎖の準備

1. scenarios.ts に `runDarkColorScheme(adapter, label)` を追加:
   - シナリオ 1: split-form.html を開く → 既存フロー (clickFillButton 等) でプレビュー パネルを開く → seam でパネル要素を取得 → executeScript で `getComputedStyle(el).backgroundColor / color` を読む → dark token (#212530 → computed `rgb(33, 37, 48)`。文字色は src/ui/overlay.ts の dark メディアブロックから実装時に読む) と一致
   - シナリオ 2: floating banner (button.ts の shadow) の computed 背景が dark token と一致 (button.ts 内 dark メディアブロックの値を実装時に読む)
   - 両シナリオで相対輝度からコントラスト比 ≥ 4.5 を計算 assert (WCAG 相対輝度定義に基づく計算関数を scenarios.ts 内ローカルに実装)
2. 相対輝度計算関数の単体テスト tests/e2e/contrast.test.ts (既知ペア: 同色 1.0 / 白黒 21 / dark token 組で PBI-209 の計算値と突合)
3. エントリファイル: tests/e2e/chrome.dark.e2e.ts と firefox.dark.e2e.ts — dark adapter を start し runDarkColorScheme を呼ぶ (既存 chrome.e2e.ts / firefox.e2e.ts の構造を踏襲)。include pattern と test:e2e:* フィルタに自動一致するため Makefile・script は触らない
4. focused: `npm run test:e2e:chrome` / `test:e2e:firefox` (HEADLESS=1) — dark シナリオ含む全 e2e 緑 → make check
5. PBI-209 の残 2 チェックは controller が e2e 結果を根拠に閉じる (実装者は結果を report に記録するのみ)
