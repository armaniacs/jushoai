# 電話番号が入らないと思ったら、「LLMで再分析」で直りました

ダッシュボードの記録ではなく、今回は問い合わせフォームのプレビューを見ていたら、こんな表示がありました。

![再分析前。電話番号の3欄に同じ長い番号が入り、文字数を超えるため入力しませんと出ます](images/before-reanalyze.png)

電話番号の3欄が全部赤字です。いそがしい人向けに結論を先に書きます。プレビューの左下にある「LLM で再分析」を押すと直ります。

![再分析後。03 / 3581 / 4321 に分かれ、AI判定バッジが付きます](images/after-reanalyze.png)

この記事は一般利用向けです。仕組みの話は最小限にして、手順だけ書きます。

## 直し方

1. フォームで「JushoAI で入力」を押します。
2. 「入力内容の確認」が出たら、赤字がないか見ます。
3. 赤字があれば「LLM で再分析」を押します。ボタンは「分析中…」に変わります。
4. 行が入れ替わったら、もう一度確認して「入力する」を押します。

今回の例では、こう変わりました。

| 欄の表示 | 再分析前 | 再分析後 |
|---|---|---|
| 電話番号の市外〜 | 0335814321 で警告 | 03 になります |
| 電話番号の市内〜 | 0335814321 で警告 | 3581 になります |
| 電話番号の加入〜 | 0335814321 で警告 | 4321 になります |

「AI判定」と紫の札が付いた行が、AIで直した行です。札がない行はルール判定のままです。

## なぜこうなるのか

このフォームは電話番号が3つに分かれています。最初の判定では3欄とも「電話番号そのもの」に見えました。そのため全部に長い番号を入れようとして、最大文字数に当たりました。再分析では3欄の並びを見て、市外局番・市内局番・加入者番号に割り振り直します。

都道府県のように「入力済みのため上書きしません」と出る行は、そのまま残ります。上書きしませんので安心です。

## 次にすること

赤字が出たら、まず「LLM で再分析」を試してみてください。それでも赤字が残る場合は、その欄は手入力で大丈夫です。JushoAIは入力済みの欄を壊しません。

Q. プロフィールの電話番号や名前がAIに送られるのでしょうか。
A. 大丈夫です。送るのは欄の名前や見出しなどの形だけです。順番に整理します。値は送りませんし、作りもしません。

Q. ボタンに「AI: OpenAI 互換」と出ていました。何ですか。
A. 設定で選んだAIの種類です。今回はOpenAI互換APIを使う設定での例です。具体的なモデル名は設定画面のモデル名の通りです。内蔵AIやGeminiを選んだ場合も、ボタンの表示と「AI判定」の札の動きは同じです。
