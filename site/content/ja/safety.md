# 安全のための仕組み

JushoAI は氏名や住所を扱います。そのため、勝手に入力しない、勝手に送らない、守りを何重にもする、を設計の前提にしています。ここでは、実際に行っていることを一覧にします。

## 入力するときの保護

- ボタンを押しても、すぐには入力しません。プレビューで欄と値を確認し、「入力する」を押したときだけ入力します。
- ページを開いただけで入力することはありません。
- 入力済みの欄は上書きしません。プレビューを開いている間に自分で入力した欄も上書きしません。
- 最大文字数を超える値は、切り詰めずに警告して入力しません。
- 読み取り専用（readonly）と無効（disabled）の欄は飛ばします。
- 郵便番号の欄は最後に入力します。住所を自動補完するフォームとの競合を避けるためです。
- 入力の途中でプレビューが消えた、画面の外に出た、隠れた、ほかの要素に覆われたときは、入力を中止します。

## 元に戻す

入力の直後は、プレビューの「元に戻す」で、JushoAI が入れた欄だけを入力前の空の状態に戻せます。あとから自分で書き足した欄は、内容が一致しないため触りません。

取り消しのための履歴は、ページの中のメモリにだけ置きます。保存も送信もせず、タブを閉じると消えます。戻せるのは直近の入力だけです。

## 値は決まった処理で作る

AI は、入力欄が何の欄かを分類するだけです。入れる値は作りません。分割、カナ変換、半角化、ハイフンの要否は、決まった処理で行います。プロファイルの値は、AI にも外部にも渡しません。

AI は初期状態でオフです。ルールで判定できない欄の補助にだけ、設定したときに使います。

## 送るデータを最小にする

AI を設定した場合に送るのは、欄のメタデータだけです。プロファイルの値、欄に入っている値、選択肢は送りません。送る項目の一覧は [プライバシーと送信データ](/guides/privacy/) にあります。

通信は「JushoAI で入力」を押したときと、設定ページで「接続テスト」を実行したときだけです。AI を呼び出すたびに、送った内容を端末内の監査ログに記録します。記録は設定ページで確認、ダウンロード、削除でき、7 日で自動的に消えます。

## 接続先の検証

クラウドの AI を使うとき、接続先は次の順で確かめます。

1. ベース URL は https のみです。http は localhost と 127.0.0.1 だけ使えます。URL に認証情報、クエリ、フラグメントを含めることはできません。
2. 内部ネットワークのアドレスは拒否します。IPv6 のアドレスは使えません。
3. 保存するときにホスト名を名前解決し、内部アドレスに解決される、または解決を確認できないときは保存を拒否します。呼び出しの直前にも、もう一度確かめます。
4. HTTP のリダイレクトは辿りません。別のホストへ転送されても、そこへは送りません。
5. 初めて使う接続先は、IP アドレスの一覧を見て承認するまで、何も送りません。

検証と実際の接続は別々の名前解決のため、その間に解決結果が変わる攻撃（DNS rebinding）を完全には排除できません。この点は [プライバシーと送信データ](/guides/privacy/) にも書いています。

## API キーと権限

API キーは AES-GCM で暗号化して保存します。鍵は取り出せない形で、別の保管場所に置きます。設定ページにはキーを表示せず、保存済みかどうかだけを表示します。接続先のオリジンを変えると、保存済みのキーは破棄します。

通信の許可は、インストール時には求めません。設定ページで保存したときに、そのプロバイダのホストだけを求めます。許可しない限り、AI は使われません。

## 画面の分離

JushoAI の画面は、閉じた Shadow DOM の中に置きます。ページ側のスクリプトからは操作できません。ページ由来の文字列（ラベルなど）は、HTML として解釈せず、文字としてだけ表示します。

## 対象外にしていること

- 別のオリジンの iframe の中にあるフォームには入力しません。
- チェックボックス、hidden、送信ボタンなどは対象にしません。
- 起動しない URL を登録したページでは、動きません。登録は [ツールバーとフォームへの入力](/guides/popup-and-fill/) を参照してください。
