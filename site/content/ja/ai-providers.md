# AI プロバイダの設定

## AI を使うかどうか

AI は必須ではありません。初期状態は「使わない（ルールのみ）」で、設定しなくてもルールによる入力がそのまま使えます。使う場合は、設定ページの「AI 判定（任意）」にある「AI プロバイダ」で選びます。

- 使わない（ルールのみ）
- ブラウザ内蔵 AI（Chrome / Edge。端末とフラグの設定が必要）
- OpenAI 互換 API（OpenAI / Groq / Mistral / Ollama / LM Studio など）
- Google Gemini

AI が担当するのは、ルールで判定できない欄の分類だけです。入力する値は作りません。仕組みは [対応するフォームと仕組み](./how-it-works.md) を参照してください。

## 送信前の確認画面（AI判定で送る内容）

AI が有効で、ルールで判定できない欄がフォームにあるときは、プロバイダに何も送る前に「AI判定で送る内容」の確認パネルが開きます。

- 送られる欄のメタデータ（`name`・`id`・`label`・`placeholder`・見出し・`type`・`maxLength`）を、送信前に画面で確かめられます。
- ラベルや見出しなどに個人情報らしき文言が含まれる欄には「（要確認）」が付き、既定で「送らない」にチェックが入っています。送ってよいと確認できた場合だけチェックを外してください。
- プレビューの「直す」で意味を教えた欄（覚えた対応付け）は、最初から除外され、AI には一切送られません。
- 「ルールのみで入力する」を押すか、Esc キーまたは閉じる操作でパネルを閉じると、何も送信せずにルールだけで入力を進めます。「AI判定する」を押したときだけ、除外されていない欄が送信されます。

## OpenAI 互換 API

プリセット（OpenAI、Groq、Mistral、Ollama、LM Studio）を選ぶと、ベース URL が自動で入ります。モデル名と API キーは自分で入力します。

ベース URL には次の条件があります。

- `https` だけが使えます。`http` は `localhost` と `127.0.0.1` に限ります。
- 認証情報、クエリ、フラグメントを含む URL は指定できません。
- 内部ネットワークのアドレスと、IPv6 アドレスは指定できません。保存時にホスト名を DNS で解決し、解決先が内部ネットワークのアドレス（プライベート IP・ループバック・リンクローカル、および NAT64 や 6to4 などの IPv6 変換プレフィックスを含む）に解決されるときや、解決を確認できないときは拒否します。nip.io・sslip.io のように、内部アドレスへ解決される名前も保存できません。
- 分類と接続テストの呼び出しの直前にも、解決先を再確認します。解決先が内部ネットワークのアドレスに解決される、または解決を確認できないときは、その呼び出しは行わず、残りの欄はルールだけで続けます。ホスト名の字句チェックも引き続き適用されます。解決結果は呼び出しごとに取り直し、前の呼び出しの結果は次の呼び出しに持ち越しません。
- ベース URL には、信頼できるプロバイダの URL のみ入力してください。

ベース URL のオリジン（スキーム・ホスト・ポート）を変えると、保存済みの API キーは引き継がれません。API キーを入力し直してください。保存済みの API キーは、「保存済みの API キーを削除する」にチェックを入れて保存すると削除できます。

保存した接続先に初めて送信する前には、設定ページでの承認が必要です。保存済みの接続先の下に、ホスト名を DNS で解決して得られた IP アドレスの一覧と「この接続先を承認する」ボタンが表示されるので、送信先が想定どおりか確かめてから承認してください。承認するまで、その接続先には何も送信しません。見覚えのないアドレスがある場合は承認せず、ベース URL を確認してください。

## Ollama と LM Studio（ローカル）

`localhost` の場合は、API キーが不要です。

Ollama は、`OLLAMA_ORIGINS` で許可していない限り、拡張機能のオリジンからの要求を 403 で拒否することがあります。Ollama 側の `OLLAMA_ORIGINS` に、次の値を許可してください。

```text
chrome-extension://<拡張機能の ID>
```

Firefox では、代わりに `moz-extension://<UUID>` を許可します。UUID は設定ページに表示され、インストールごとに変わります。再インストール後は設定し直してください。

## Google Gemini

次の 3 つを設定します。

- モデル名
- API バージョン（既定は `v1beta`）
- API キー

送信先は Google の固定のエンドポイントで、利用者が変えられません。そのため、保存した接続先の検証（呼び出し直前の名前解決の再確認）は行いません。

## ブラウザ内蔵 AI

端末の中で動き、端末の外には送りません。Chrome と Edge では、ブラウザのフラグを有効にして、再起動します。

| ブラウザ | モデル | フラグ |
|---|---|---|
| Chrome | Gemini Nano | `chrome://flags/#prompt-api-for-gemini-nano` |
| Edge | Phi-mini | `edge://flags/#edge-llm-prompt-api-for-phi-mini` |

モデルのダウンロードは、「JushoAI で入力」を押すと試みます。ブラウザによっては、自動では始まりません。

Firefox にはブラウザ内蔵 AI（Prompt API）がないため、この選択肢は表示されず利用できません。以前の環境などで内蔵 AI が保存されていた設定を Firefox で読み込んだ場合は、自動的にルールのみ（「使わない」）へ切り替わり、設定ページにその旨が表示されます。

## 接続テストとバッジの見方

設定ページの「接続テスト（保存済みの設定で実行）」は、保存済みの設定で、合成した 1 欄を分類させます。先に「保存」してから試してください。連打による過剰な送信を防ぐため、テストの実行直後は約 3 秒間ボタンが無効化され、続けて押しても追加のリクエストは発生しません。

結果は、「接続できました」か、次のいずれかです。

- 設定が完了していない → 設定ページで入力し直します
- 通信が許可されていない → 設定ページで保存し直し、許可します
- 認証に失敗した → API キーを確認します
- サーバーが拒否した → モデル名と、モデルが JSON 形式の出力に対応しているかを確認します
- 接続に失敗した → URL、モデル名、ネットワークを確認します
- 応答を解釈できなかった → モデルが JSON 形式の出力に対応しているかを確認します

フォーム上のバッジは、AI の状態を示します。バッジを押すと、状態に応じた案内が開きます。設定が必要な状態では、「AI 設定を開く」ボタンがあります。バッジごとの対処は [トラブルシューティング](./troubleshooting.md) にあります。

1 回の「入力」で AI に送る欄は最大 60 欄で、20 欄ずつ送ります。1 回でも失敗したら、残りは送らず、ルールだけで続けます。OpenAI 互換 API では、HTTP 400 か 422 で拒否されたときは、互換形式（temperature なし、`json_object`）で 1 回だけ再試行します。

## 通信の許可

設定を保存すると、そのプロバイダへの通信の許可を、ブラウザが確認します。許可しないと AI は使われず、バッジは「AI 権限なし」になります。許可は、そのプロバイダのホストと、保存時と呼び出し直前の検証に使うリゾルバ（dns.google）に求めます。許可はホスト単位で、ポートを区別しません。同じホストの別のポートにも許可が及びます。実際に送る先は、保存した接続先に限られます。

Firefox では、クラウドプロバイダを保存するときにホストの許可とあわせて、ウェブサイトのコンテンツ（入力欄のメタデータ）をプロバイダへ送ることへの同意（データ収集の権限）も求めます。詳しくは [プライバシーと送信データ](./privacy.md) を参照してください。

## 通信ログの確認

API との通信は、設定ページの「通信の監査ログ」で確かめられます。端末内に 7 日間保存します。日時、プロバイダ、宛先、モデル、ページの URL（オリジンのみ）、送った欄の数、結果に加えて、モデルに送ったプロンプトとモデルの応答が記録されます。一覧の確認、TSV ダウンロード、削除ができます。プロファイルの値は記録しません。詳しくは [プライバシーと送信データ](./privacy.md) を参照してください。
