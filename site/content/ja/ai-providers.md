# AI プロバイダの設定

## AI を使うかどうか

AI は必須ではありません。設定ページの「AI 判定（任意）」にある「AI プロバイダ」で選びます。

- 使わない（初期値）
- ブラウザ内蔵 AI
- OpenAI 互換 API
- Google Gemini

AI が担当するのは、ルールで判定できない欄の分類だけです。入力する値は作りません。仕組みは [対応するフォームと仕組み](/guides/how-it-works/) を参照してください。

## OpenAI 互換 API

プリセット（OpenAI、Groq、Mistral、Ollama、LM Studio）を選ぶと、ベース URL が自動で入ります。モデル名は自由に入力します。API キーも入力します。

ベース URL には次の条件があります。

- `https` だけが使えます。`http` は `localhost` と `127.x.x.x` に限ります。
- 認証情報、クエリ、フラグメントを含む URL は指定できません。
- 内部ネットワークのアドレスと、IPv6 アドレスは指定できません。保存時にホスト名を DNS で解決し、解決先が内部ネットワークのアドレス（プライベート IP・ループバック・リンクローカル）に解決される・解決を確認できないときは拒否します。nip.io・sslip.io のように、内部アドレスへ解決される名前も保存できません。
- 分類と接続テストの呼び出しの直前にも、解決先を再確認します。解決先が内部ネットワークのアドレスに解決される・解決を確認できないときは、その呼び出しは行わず、残りの欄はルールだけで続けます。ホスト名の字句チェックは引き続き適用されます。解決結果は呼び出しごとに取り直し（per-call）、前の呼び出しの結果は次の呼び出しに持ち越しません。
- ベース URL には、信頼できるプロバイダの URL のみ入力してください。

ベース URL のオリジン（スキーム・ホスト・ポート）を変えると、保存済みの API キーは引き継がれません。API キーを入力し直してください。保存済みの API キーは、「保存済みの API キーを削除する」にチェックを入れて保存すると削除できます。

保存した接続先に初めて送信する前には、設定ページでの承認が必要です。保存済みの接続先の下に、ホスト名を DNS で解決して得られた IP アドレスの一覧と「この接続先を承認する」ボタンが表示されるので、送信先が想定どおりか確かめてから承認してください。承認するまで、その接続先には何も送信しません。見覚えのないアドレスがある場合は承認せず、ベース URL を確認してください。

## Ollama と LM Studio（ローカル）

`localhost` の場合は、API キーが不要です。

Ollama は、`OLLAMA_ORIGINS` で許可していない限り、拡張機能のオリジンからの要求を 403 で拒否することがあります。Ollama 側の `OLLAMA_ORIGINS` に、次の値を許可してください。

```text
chrome-extension://<拡張機能の ID>
```

Firefox では、代わりに `moz-extension://<UUID>` を許可します。UUID は設定ページに表示され、インストールごとに変わります。

## Google Gemini

次の 3 つを設定します。

- モデル名
- API バージョン（既定は `v1beta`）
- API キー

送信先は Google の固定のエンドポイントで、利用者が変えられません。そのため、保存した接続先の検証（呼び出し直前の名前解決の再確認）は行いません。

## ブラウザ内蔵 AI

端末の中で動き、端末の外には送りません。Chrome と Edge では、ブラウザのフラグを有効にして、再起動します。Firefox ではブラウザ内蔵 AI は使えません。

| ブラウザ | モデル | フラグ |
|---|---|---|
| Chrome | Gemini Nano | `chrome://flags/#prompt-api-for-gemini-nano` |
| Edge | Phi-mini | `edge://flags/#edge-llm-prompt-api-for-phi-mini` |

モデルのダウンロードは、「JushoAI で入力」を押すと試みます。ブラウザによっては、自動では始まりません。

## 接続テストとバッジの見方

設定ページの「接続テスト（保存済みの設定で実行）」は、保存済みの設定で、合成した 1 欄を分類させます。先に保存してから試してください。接続テストの直後は約3秒間ボタンが無効化され、連打しても追加のリクエストは発生しません。

結果は、「接続できました」か、次のいずれかです。

- 設定が完了していない → 設定ページで入力し直します
- 通信が許可されていない → 設定ページで保存し直し、許可します
- 認証に失敗した → API キーを確認します
- サーバーが拒否した → モデル名と、モデルが JSON 形式の出力に対応しているかを確認します
- 接続に失敗した → URL、モデル名、ネットワークを確認します
- 応答を解釈できなかった → モデルが JSON 形式の出力に対応しているかを確認します

フォーム上のバッジは、AI の状態を示します。バッジを押すと、状態に応じた案内が開きます。設定が必要な状態では、「AI 設定を開く」ボタンがあります。バッジごとの対処は [トラブルシューティング](/guides/troubleshooting/) にあります。

1 回の「入力」で AI に送る欄は最大 60 欄で、20 欄ずつ送ります。1 回でも失敗したら、残りは送らず、ルールだけで続けます。OpenAI 互換 API では、HTTP 400 か 422 で拒否されたときは、互換形式（temperature なし、`json_object`）で 1 回だけ再試行します。

## 通信の許可

設定を保存すると、そのプロバイダへの通信の許可を、ブラウザが確認します。許可しないと AI は使われず、バッジは「AI 権限なし」になります。許可は、そのプロバイダのホストと、保存時と呼び出し直前の検証に使うリゾルバ（dns.google）に求めます。許可はホスト単位で、ポートを区別しません。同じホストの別のポートにも許可が及びます。実際に送る先は、保存した接続先に限られます。詳しくは [プライバシーと送信データ](/guides/privacy/) を参照してください。

## 通信ログの確認

API との通信は、設定ページの「通信の監査ログ」で確かめられます。端末内に 7 日間保存します。日時、プロバイダ、宛先、モデル、ページの URL、送った欄の数、結果に加えて、モデルに送ったプロンプトとモデルの応答が記録されます。一覧の確認、TSV ダウンロード、削除ができます。プロファイルの値は記録しません。詳しくは [プライバシーと送信データ](/guides/privacy/) を参照してください。
